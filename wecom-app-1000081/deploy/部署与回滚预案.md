## 2. 部署步骤（Gate 1→4）

### Gate 1：环境准备（刘总确认服务器 + 登录方式）
- 目标机：现有 AI 服务器 `115.159.101.193`（同机隔离，不新建 CVM）；系统 Ubuntu 22.04 / TencentOS；
- 复用已有 Node 22 / PM2 / nginx（若版本足够，不重装）；仅新增独立目录、PM2 进程、nginx 站点；
- 开放安全组：入站 80、443（企微回调）、22（或仅 TAT）。

### Gate 2：代码与配置下发
- 将 `wecom-app-1000081/` 上传至 `/opt/holang/wecom-app-1000081/`；
- `npm install --production`；
- **由刘总/运维在服务器创建 `.env`**（填入 D1 真实值），`chmod 600 .env`；
- 放 `ecosystem.config.json` 至项目根。

### Gate 3：nginx 与启动
- 放 `deploy/nginx-wecom-1000081.conf` → `/etc/nginx/conf.d/`，改 `server_name` 为真实域名、SSL 路径；
- `nginx -t && systemctl reload nginx`；
- `pm2 start ecosystem.config.json`；
- 验证：`curl https://<域名>/health` 返回 `{"status":"ok",...}`。

### Gate 4：企微端联调与验收
- 企微后台 1000081 → 接收消息 → 填 Token/EncodingAESKey/Secret，回调 URL=`https://<域名>/wecom/1000081/callback`；
- 点"保存"时企微发起 **GET URL 验证** → 服务验签返回明文即通过；
- 员工给 1000081 发消息 → 企微 **POST** 推送 → 服务解密+记录（当前默认空回，见蓝图扩展点）；
- 验收清单：GET 验证 ✅ / POST 解密 ✅ / access_token 获取 ✅ / 日志审计 ✅。

> **禁止半成品**：任一 Gate 未过，不进下一阶段；部署中发现 D1–D4 缺失立即回退并上报。

## 3. 回滚预案

| 场景 | 回滚动作 | 影响 |
|------|----------|------|
| PM2 启动异常 | `pm2 stop wecom-app-1000081` 或 `pm2 rollback`（若用过 deploy） | 仅本服务停，AI 服务不受影响 |
| nginx 配置错误 | `mv conf /tmp && nginx -t && systemctl reload nginx` 还原 | 仅 1000081 回调不可达 |
| 代码回归 | `git checkout` 上一稳定版本或保留部署包备份 `/opt/holang/backup/` | 可秒级回退 |
| 凭证泄露 | 立即在企微后台**重置** 1000081 Secret/Token/AESKey，更新服务器 `.env` 并重启 | 旧凭证失效，需重新 GET 验证 |

- 备份：每次部署前 `tar czf /opt/holang/backup/wecom-1000081-<时间戳>.tgz /opt/holang/wecom-app-1000081`。
- 监控：`/health` 接入服务器监控；错误日志 `/var/log/holang/wecom-1000081-*.log`。
