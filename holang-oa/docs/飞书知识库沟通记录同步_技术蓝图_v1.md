### 安全闸门（tech-lead 强制，防"全自动"误伤）
1. **分类型开关 + 总闸**：配置文件 `feishu-wiki.json` 中 `enabled`（总闸）、`syncFollowUp`/`syncAiThread`/`syncContactNote`（三类独立开关）。任一类关闭即不推。
2. **AI 对话改为"会话级自动归档"**：不在每次 AI 消息时实时推，而是**当一段对话结束**（销售点「归档到飞书」或系统检测到该客户对话静默 ≥ 30 分钟）时，把该段对话聚合成**一个文档**自动推送。仍属"全自动"，只是粒度是会话而非消息。
3. **失败入库待补**：飞书 API 异常/限流时写入本地 `feishu_sync_log.status=FAILED` 并记录错误，提供手动重推入口（PENDING 自动重试队列为后续增强）。
4. **幂等防重**：每条记录用 `client_token`（= `oa:<recordType>:<oaRecordId>`）调飞书创建节点，重试不产生重复；重推时先删旧节点再建新节点。
5. **空内容跳过**：content/remark 为空不推，避免垃圾节点。
6. **RBAC 继承**：写入/重推（resync/batch）需 ADMIN；检索与正文调取需登录用户（沟通档案为团队复用资产，读取面向全体员工，符合"便于复用"诉求）。

## 2. 飞书对接接口与鉴权（精确契约）

### 2.1 鉴权（飞书应用身份 = tenant_access_token，方案 A）
- 复用 `api-config` 中 `feishu.appId`/`appSecret`，调用 `POST {baseUrl}/auth/v3/tenant_access_token/internal` 获取 `tenant_access_token`。
- 服务端内存缓存 token，过期前 300s 自动刷新（expire=7200s）。
- **所有写入与读取**飞书知识库的请求统一带 `Authorization: Bearer <tenant_access_token>`。
- **无 OAuth、无 user_access_token、无 refresh_token、无回调 URL**。

### 2.2 建知识库节点（文档）
```
POST {baseUrl}/wiki/v2/spaces/{space_id}/nodes
Body: {
  "obj_type": "docx",
  "parent_node_token": "<可选，按 客户/年/月 归档的父节点>",
  "node_name": "<文档标题>",
  "client_token": "oa:<recordType>:<oaRecordId>"   # 幂等
}
Resp: { "data": { "node": {
  "space_id":"...", "node_token":"...", "obj_token":"doxcxxx",
  "obj_type":"docx", "parent_node_token":"...", "node_name":"...", "url":"https://.../wiki/..."
}}}
```
> 约束：应用身份写入，须该应用为空间成员且有写权限（截图显示「可管理」，已满足）。否则返回 403。

### 2.3 写文档正文（块）
```
POST {baseUrl}/docx/v1/documents/{obj_token}/blocks/{obj_token}/children?document_revision_id=-1
Body: { "children": [ { "block_type": 2, "text": { "elements": [ { "text_run": { "content": "..." } } ] } } ] }
```
- `block_type=2` 文本块；用多个文本块分段（标题/元信息/内容/页脚），保证稳健渲染。
- 重推时先 `DELETE /wiki/v2/spaces/{space_id}/nodes/{node_token}` 删旧文档，再建新。

### 2.4 读文档正文（拉取/调取）
```
GET {baseUrl}/docx/v1/documents/{obj_token}/blocks/{obj_token}?document_revision_id=-1
→ 遍历 children 还原为纯文本，用于 OA 内"拉取查看"
```

### 2.5 前置连通性校验（落地第一步）
```
POST /api/v1/feishu-wiki/setup/verify
→ 取 tenant_access_token → 调 wiki/v2/spaces/{space_id} 校验空间可访问
→ 返回 { ok, spaceName, canWrite, tokenReady }
```
`canWrite` 取乐观值（应用历史已写通）；真实写权限在首次 push 时由飞书返回确认。

## 3. 沟通记录结构化字段与入库格式

### 3.1 统一文档结构（飞书 docx 内容模板）
每个沟通记录 → 一篇飞书文档，固定结构保证可追溯 + 可复用：

```
# <客户名> · <类型标签> · <业务日期>

## 元信息
来源系统：HOLANG OA
OA 记录 ID：<oaRecordId>
客户：<customerName> (code: <customerCode>)
关联联系人：<contactName>
方式/渠道：<method> / <channel>
操作人：<operator>
业务时间：<followedAt>
同步时间：<syncedAt>
OA 原文链接：<oaUrl>

## 内容
<content / AI 对话逐轮文本 / 联系人备注>

## 下一步计划（仅跟进）
<nextPlan>

---
本文由 HOLANG OA 自动同步 · recordId=<oaRecordId> · 如需修改请回 OA 编辑后重新同步
```

### 3.2 三类记录字段映射

| 飞书文档字段 | FollowUp | CustomerAiMessage(线程) | Contact.remark |
|---|---|---|---|
| 类型标签 | 跟进记录 | AI 对话归档 | 联系人备注 |
| 标题 | `{客户}·跟进·{业务日期}` | `{客户}·AI对话·{日期}` | `{客户}·联系人·{姓名}` |
| content | `content` | 该段对话 user/assistant 逐轮拼接 | `remark` |
| 关联联系人 | `contactId→name` | — | 本人（即该联系人） |
| 方式/渠道 | `method`/`channel` | `model` | — |
| 操作人 | `operator`/`user.name` | `user.name` | `createdBy.name` |
| 业务时间 | `followedAt` | 线程最后消息时间 | `createdAt` |
| 下一步 | `nextPlan` | — | — |

## 4. 数据模型与配置

### 4.1 Prisma 新增模型
```prisma
model FeishuSyncLog {
  id          String   @id @default(cuid())
  recordType  String   // FOLLOW_UP | AI_THREAD | CONTACT_NOTE
  oaRecordId  String   // 原表 PK
  customerId  String
  customerName String?
  operator    String?
  title       String
  nodeToken   String   // 飞书节点 token（删/更新用）
  objToken    String   // docx obj_token（读正文用）
  feishuUrl   String
  status      String   @default("SYNCED") // SYNCED | FAILED
  lastError   String?
  retryCount  Int      @default(0)
  syncedAt    DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@unique([recordType, oaRecordId])
  @@index([customerId])
  @@index([status])
  @@map("feishu_sync_log")
}
```

### 4.2 配置存储
- **飞书凭证**：复用 `api-configs.json` 中 `feishu.credentials`（`appId`/`appSecret`），不新建。
- **同步开关与空间**：独立文件 `config/feishu-wiki.json`：
```json
{
  "enabled": true,
  "syncFollowUp": true,
  "syncAiThread": false,
  "syncContactNote": false,
  "wikiSpaceId": "7598114727864159200",
  "aiIdleMinutes": 30
}
```
（Phase 1 仅 `syncFollowUp` 默认开；AI/联系人开关预留，Phase 2/3 接好后开启。）

## 5. 后端接口契约

| Method | Path | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/v1/feishu-wiki/setup/verify` | 校验 token+空间可访问，返回空间名 | ADMIN |

| GET | `/api/v1/feishu-wiki/records/:id` | 拉取：从飞书读回文档正文返回纯文本 | 登录用户 |
| POST | `/api/v1/feishu-wiki/records/:oaRecordId/resync` | 手动单条重推 | ADMIN |
| POST | `/api/v1/feishu-wiki/batch-sync` | 手动批量推（body: `{ids:[],type}`） | ADMIN |
| GET | `/api/v1/feishu-wiki/settings` | 读同步开关 | ADMIN |
| PUT | `/api/v1/feishu-wiki/settings` | 改同步开关/spaceId | ADMIN |

### 自动触发埋点（Phase 1）
- `followUp.controller.ts` create 成功 → `feishuWiki.pushFollowUp(record)`（开关开时，fire-and-forget）

### 检索逻辑（满足"按关键词或条件查询并拉取"）
- **列表检索**：查本地 `feishu_sync_log`（联 customer 取名称），支持 `keyword`（匹配 title/customerName/operator/oaRecordId）、`customerId`、`type`、`from/to` 时间区间、分页。返回含 `feishuUrl` 直链。
- **正文调取**：`GET /records/:id` → 用 `objToken` 调飞书 docx 读块接口还原正文，OA 内直接看，不必跳飞书。
