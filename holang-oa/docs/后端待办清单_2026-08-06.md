## 二、任务明细

### 组A：快速新增联系人 同步到 PI/商机表单（后端收尾）

**背景**：复用组件 `QuickAddContactSelect` 已在客户详情→时间轴→添加跟进的联系人下拉上线（来源③）。本次刘总要求扩展到 PI 表单 / 商机表单。经核实，这两表单原用**模拟客户数据**且商机/PI **无联系人字段**，故后端须补 `customerContactId` 落库；联系人必须挂真实后端客户（`POST /customers/{id}/contacts`），前端配套切真实客户源（前端任务，见末节）。

**来源①**：用户消息「把『快速新增联系人』同步接到 PI 表单 / 商机表单的联系人选择处」

- **A1 Opportunity 落库 `customerContactId`**
  - 描述：Opportunity 模型加 `customerContactId String?` + 索引；repository `CreateOpportunityInput`/`createOpportunity`/`updateOpportunity` 透传；service 透传；controller `createOpportunitySchema` 接收。
  - 当前状态：代码全链路已写完（schema/repo/service/controller 均已含 `customerContactId`）。
  - 风险：additive（可空字段），不破坏现有编译；未编译未部署。

- **A2 Pi 创建路径落库 `customerContactId`**
  - 描述：Pi 模型加 `customerContactId String?` + 索引；repository `CreatePiInput`/`createPi` 透传；service `CreatePiInput`/`createPi` 透传；controller `createPiSchema` 接收。
  - 当前状态：repo（L19/L46）、service（L24/L70）、controller create schema（L21）均已含 `customerContactId`。

- **A3 Pi 新增 `updatePiContact` 更新联系人接口**
  - 描述：新增 `PATCH/PUT /pis/:id/contact` 接口，更新 Pi 的 `customerContactId`（可选置空）。含控制器 handler + 路由注册 + 审计。
  - 当前状态：repository `updatePiContact`（L124）与 service `updatePiContact`（L147）**已写**；**控制器 handler + 路由注册未加**（上次网络中断处）。若现在部署该接口会 404。
  - 落地动作：补 controller handler + route，再随组A一并部署。

- **A4 后端构建 + 增量部署（组A 全量）**
  - 描述：prisma generate → db push（SQLite 加可空列，保数据）→ 定向 tar 增量覆盖 `/opt/holang/oa/backend` → PM2 restart `holang-oa-backend`。**严禁全量 `oa_deploy_backend.py`（会删生产库）**。
  - 当前状态：未做。须等 A3 补齐后再整体部署。

### 组B：商机 M2M 协作 + 贡献拆分（任务#54 后端）

**背景**：`Opportunity` 模块已存在（CRUD + 索引 + 漏斗/预测），本次为增强。刘总已拍板两项决策：①删客户时**合约/订单拦截**、仅级联删商机；②业绩按**实际订单/合同未税额**拆分（未成交仅进预测）。技术蓝图 + 高保真原型已完成待会签。

**来源②**：用户消息「为同一客户设计并实现数据模型与关联逻辑，支持客户关联无限数量的商机记录……设计销售业绩按贡献度拆分分配的建模与逻辑……」

- **B1 schema 新增两张 M2M 表**
  - 描述：`CustomerSales`（客户↔销售负责人，含 `role`/`isPrimary`）；`OpportunitySales`（商机↔协作销售，含 `contributionRate` 0–100）。替代原 `Opportunity.collaborators` JSON 字符串 hack。
  - 当前状态：未做（蓝图 `docs/商机M2M协作与贡献拆分技术蓝图_v1.md` 已定）。

- **B2 级联删除逻辑**
  - 描述：`Opportunity.customer` 加 `onDelete: Cascade`（Prisma+SQLite 在 Client 层生效）；删客户→级联删商机→级联删 `OpportunitySales`。`customer.controller.deleteCustomer` 改为：有关联合约/订单则**拦截**，仅级联删商机。
  - 当前状态：未做（现状 `deleteCustomer` 反而 400 拦截"有关联商机无法删除"，须改为级联）。

- **B3 价格口径统一**
  - 描述：补 `Contract.amountWithoutTax` / `Pi.amountWithoutTax`；新增 `backend/src/utils/price.ts` 集中 `calcUntaxed(amount, taxRate)`。奖金一律未税、外销 taxRate=0 仅未税、合同按未税汇总。
  - 当前状态：未做。

- **B4 商机协作 M2M 服务/控制器**
  - 描述：商机协作成员的增/删/改/查；单人 `contributionRate` 0–100，**单商机比例之和须=100**（后端校验，非 100 返回 400）。保留 `salesOwnerId` 主负责冗余，约束主负责必在 M2M 且 `isPrimary=true`。
  - 当前状态：未做。

- **B5 销售业绩按贡献拆分聚合接口**
  - 描述：新增业绩聚合（只读计算，不落库防漂移）：某销售未税业绩 = Σ(商机实现未税额 × 该人贡献比例/100)；来源 `Order`/`Contract`/`Pi.amountWithoutTax` → 关联商机 → `OpportunitySales` 比例；外销仅未税；奖金同未税。
  - 当前状态：未做。

- **B6 后端构建 + 增量部署（组B 全量）**
  - 描述：同 A4 流程，但涉及新表 + 级联 + 价格字段结构性变更，须严格走 `prisma db push` 保数据。
  - 当前状态：未做。
