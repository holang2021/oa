# OA-REL-010：预发布发布清单与运维验收设计

日期：2026-10-26
状态：设计完成；实际预发布部署、服务器操作与生产变更未开始。
发布候选：仅允许通过全部前置门禁的固定 Git SHA；当前待验证候选为 `system-build` 的 `ca519c5`，不等同于可发布版本。

## 发布前置门禁

- `OA-ENV-004`：锁文件依赖恢复、`bcrypt`、后端测试与前后端构建均已通过；Puppeteer 浏览器功能待预发布验证。
- `OA-CRM-002`：自动化通过；CR-01 至 CR-07 浏览器/API 业务链路与受控测试数据验收待完成。
- `OA-DB-001`：独立 PostgreSQL 测试库、数据核对和回滚演练待完成。
- `OA-SEC-007`：敏感值轮换、默认管理员禁用和环境隔离待批准实施。
- 不满足任一门禁时，发布清单状态为“中止”，不得进入部署。

## 唯一预发布发布路径（待实施验证）

1. 固定候选 SHA、依赖锁文件摘要、后端/前端构建产物摘要和测试报告。
2. 使用现有 PM2/TAT 形态在预发布环境部署；Docker 路径在独立修复和验收前不参与本次路径。
3. 统一声明预发布端口、唯一健康检查 URL、PM2 进程名、日志位置与失败阈值；当前资料存在不一致，实施前必须以本清单更新后的版本为准。
4. 执行“部署→健康检查→CRM 烟雾→回滚→数据库恢复→再次健康检查”闭环。
5. 形成脱敏证据包，提交 UAT 与生产变更批准；未经批准不得推广到生产。

## 运维验收清单

| 项目 | 通过条件 | 证据 |
|---|---|---|
| 服务存活 | 进程重启后服务正常、健康端点返回预期 | 时间、候选 SHA、脱敏响应摘要 |
| 日志 | 访问/错误日志可定位且脱敏；有保留和轮转策略 | 路径、保留期、轮转规则和样例摘要 |
| 监控告警 | 服务、健康端点、磁盘、备份失败与错误率有告警，且通知闭环已测试 | 告警规则标识与测试记录 |
| 备份恢复 | 数据库备份可校验、可恢复到隔离环境并经业务核对 | SHA-256、恢复时间、核对记录 |
| 业务烟雾 | CRM 核心链路按角色和销售域通过 | `OA-CRM-002` 执行记录 |
| 回滚 | 回到上一应用版本和验证数据状态后可用 | 回滚步骤、结果与健康检查记录 |

## 失败判定与中止条件

- 候选 SHA、构建产物、环境配置或数据库版本无法追溯。
- 健康检查、CRM 烟雾、备份恢复、日志脱敏、告警闭环或回滚任一项失败。
- 检出未轮换的暴露敏感值、默认管理员仍可用于生产或跨环境访问。
- 发生以上任一情况，立即中止发布，保留脱敏证据并回到上一已验证状态；不得现场修复后跳过复测。

## 实施审批点

连接预发布环境、改动 PM2/TAT、CI/CD、日志、监控、备份、DNS、端口、数据库或任何生产配置前，必须给出精确变更、恢复方式与责任人并取得明确批准。
