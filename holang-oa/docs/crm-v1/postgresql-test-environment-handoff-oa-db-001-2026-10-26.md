# OA-DB-001：PostgreSQL 隔离测试库交接规格

日期：2026-10-26
状态：可交接；未创建数据库、账号、连接串或网络规则。
用途：让环境责任人提供可复现、最小权限、非生产的 PostgreSQL 测试环境；不在本文、聊天或仓库中填写真实凭据。

## 环境边界

| 项目 | 要求 |
|---|---|
| 环境 | 独立于开发 SQLite、预发布和生产；禁止复用生产主机、数据库、账号或网络通道。 |
| 数据库 | 一个全新的、空的测试数据库；名称由环境责任人确定并记录在受控环境中。 |
| 数据来源 | 仅使用经 SHA-256 校验的 SQLite 快照或经批准的脱敏样本；源库全程只读。 |
| 网络 | 仅允许指定测试执行端或受控 CI 访问；启用 TLS 或等效受控内网保护。 |
| 生命周期 | 环境责任人记录创建人、用途、到期日和恢复点；禁止自动删除。 |

## 最小角色分离

| 角色 | 权限 | 使用阶段 |
|---|---|---|
| 迁移角色 | 仅目标测试库的 schema 创建、变更与迁移记录权限；不是超级用户 | 建立 PostgreSQL 基线与迁移演练 |
| 应用角色 | 仅目标 schema 的 DML 与连接权限；不允许创建数据库或角色 | 应用、自动化和浏览器回归 |
| 只读核验角色（可选） | 仅查询目标 schema | 数据行数、聚合与关联核对 |

真实连接信息仅通过受控秘密变量或环境责任人批准的安全渠道注入；不得写入 `.env`、文档、测试快照、命令历史或 CI 输出。

## 交接前检查

1. 环境责任人确认该实例与生产完全隔离，且没有生产数据。
2. 主线记录候选 Git SHA、当前 Prisma schema SHA 和 SQLite 快照 SHA-256。
3. 迁移角色与应用角色分别连接空库，确认最小权限有效；连接日志不包含秘密。
4. 主线创建 PostgreSQL 专用测试 setup，明确阻断非测试主机与 SQLite 源库 URL。
5. 仅在以上检查通过后生成独立 PostgreSQL 基线和导入演练记录。

## 交付给主线的非敏感信息

- 环境标识、PostgreSQL 主版本、网络访问方式、TLS 要求。
- 已建立的角色名称和权限范围（不包含口令或连接串）。
- 受控秘密变量的名称，不包含值。
- 环境负责人与故障联系路径。
- 允许执行迁移、数据导入、备份恢复演练的时间窗口。

## 验收与回退

- 空库可由独立 PostgreSQL 基线重复建立，且不重放 SQLite 方言历史迁移。
- 导入后通过记录数、主键、唯一键、关联、金额聚合和业务链路核对。
- 回退演练仅回到保留的 SQLite 快照与上一应用版本；不在测试阶段执行破坏性 down migration。
- 测试环境、导入日志和失败证据保留至阶段验收完成；后续清理必须另行批准。

## 需要的明确授权

环境责任人或用户需明确批准：创建隔离测试库、创建最小权限角色、提供受控秘密变量、允许主线执行 PostgreSQL 基线迁移与测试数据装载。获得该授权前，主线仅维护设计与验收清单。
