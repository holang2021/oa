# OA-DB-001：PostgreSQL 迁移与回滚设计

日期：2026-10-26
状态：设计完成；测试库准备与任何迁移均待明确批准。
范围：仅从当前 SQLite 运行形态迁移到**独立 PostgreSQL 测试库**的设计。本文不创建数据库、不写入配置、不改 Prisma schema、不运行迁移。

## 决策

采用“并行基线迁移 + 可回退切换”，不在 PostgreSQL 上直接重放现有 SQLite 迁移历史。

理由：当前 `schema.prisma` 仍为 SQLite，所有枚举降级为 `String`；现有迁移同时包含 PostgreSQL 的 `CREATE TYPE ... ENUM` 与 SQLite 的 `ALTER TABLE ... DEFAULT 0` 写法，历史不可作为单一目标库的可重放链。当前 Vitest 也明确只接受 `file:` SQLite URL。因此，直接切换 `provider` 或对真实库执行 `migrate dev` 都会把验证、数据转换与切换风险混在一起。

## 边界与对象锁

| 项目 | 约束 |
|---|---|
| 源数据库 | 当前 SQLite 为唯一运行源；迁移期间仅生成校验后的只读快照，不直接写入。 |
| 目标数据库 | 仅独立 PostgreSQL 测试库；名称、主机、账号和连接串均需批准后由受控环境提供，禁止写入仓库。 |
| 迁移历史 | 保留现有 `prisma/migrations/` 原样；新增 PostgreSQL 基线须放在单独目标目录，直到通过验收并批准切换。 |
| 应用切换 | 只在 PostgreSQL 测试库完成数据/流程验收后评审；生产切换、部署与回滚不属于本工作项。 |
| 对象锁 | 预留 `backend/prisma/`、PostgreSQL 基线目录、PostgreSQL 测试设置；本设计阶段仅写 `docs/crm-v1/`。 |

## 已核对证据

- 阶段 0 的运行数据库是 SQLite，基线记录为 2026-10-13；当时后端 14 个测试文件、102 项测试通过。
- 当前 `backend/prisma/schema.prisma` 使用 `provider = "sqlite"`，并明确标注所有 Prisma Enum 已转为 String。
- 当前有 6 个历史迁移目录；其中 `20260702_add_businessline_and_orders` 使用 PostgreSQL Enum SQL，而 `batch1a_customer_grade_public_pool` 使用 SQLite 布尔默认值语法，存在目标方言分叉。
- `backend/vitest.setup.ts` 复制当前 SQLite 文件至测试副本，并在发现非 `file:` URL 时直接失败；不能用于 PostgreSQL 验收。
- 阶段 0 后新增的客户、伙伴、商机、订单和回款流程，必须纳入目标库验收，但不改变本次迁移设计范围。

## 实施设计（批准后执行）

1. **源快照门禁**：停止源库写入窗口或采用已验证的一致性快照；记录文件 SHA-256、表记录数和导出时间。任何不满足一致性要求的快照立即弃用。
2. **目标库隔离**：创建最小权限的 PostgreSQL 测试数据库与迁移角色；连接串只通过受控运行环境注入，设置连接超时并禁止连接生产主机。创建数据库、账号、权限或秘密均需单独批准。
3. **目标 schema 基线**：从当前权威 Prisma schema 生成一个独立 PostgreSQL 基线目录和迁移记录。首轮保持字段名、表名、字符串状态值、金额 `Float` 与 JSON 字符串字段语义不变；不趁迁移引入 enum、JSONB、金额精度重构或业务模型变更。
4. **数据装载**：以 SQLite 快照为只读源，按外键依赖顺序装载，并保留主键与 `huobanId`。每张表使用可重试批次及已导入/已验证状态记录，禁止对源库调用 Prisma 写操作。
5. **校验**：比对全部表的行数、主键集合、唯一键冲突、关联悬挂记录、金额聚合、日期范围及抽样业务链路。源与目标的差异必须分类为“已批准转换规则”或“阻断问题”，不得静默忽略。
6. **应用与测试适配**：为 PostgreSQL 新建独立测试 setup，不复用只支持 SQLite 的 `vitest.setup.ts`；先在隔离库执行 TypeScript 构建、自动测试和客户→商机→报价/合同或 PI→订单→回款回归链路。
7. **回滚演练**：测试阶段只回退到保留的 SQLite 快照与当前 SQLite 应用版本；不在 PostgreSQL 中尝试破坏性 down migration。通过演练后才可提出生产切换方案。

## 类型与兼容性策略

| 当前形态 | PostgreSQL 首轮策略 | 后续决策 |
|---|---|---|
| `String` 状态/角色/业务分类 | 继续保持文本字段和现有应用校验 | 业务字典稳定后另案评估数据库 enum 或约束 |
| `Boolean` | 使用 PostgreSQL 原生布尔值，并逐项验证默认值 | 无需与业务重构绑定 |
| `DateTime` | 使用 Prisma 对应 PostgreSQL 时间类型，验证时区与空值语义 | 上线前固定应用时区策略 |
| 金额 `Float` | 首轮保持现有语义，做总额与明细汇总核对 | 财务精度改造须单独立项为 decimal/货币模型 |
| JSON 字符串字段 | 首轮保持文本，防止查询行为变化 | JSONB 优化须单独迁移与回滚设计 |
| 级联关系 | 逐项核对 Prisma relation 与目标库实际 FK 行为 | 不把 SQLite 的客户端级联假设直接当作 PostgreSQL 结论 |

## 验收标准

- PostgreSQL 测试库可由独立迁移记录从空库重复建立；不得依赖 SQLite 历史迁移的偶然副作用。
- SQLite 快照、导入日志、行数与聚合核对结果均可回读，且不含凭据或真实敏感字段明文。
- PostgreSQL 专用自动测试通过，并证明不会连接或写入 SQLite 源库。
- 核心链路在 PostgreSQL 测试库通过：客户、伙伴、商机、报价/合同或 PI、订单、回款。
- 回滚演练可恢复到已保留的 SQLite 快照与上一应用版本；生产切换尚未发生。

## 风险与审批点

| 风险 | 控制 | 审批点 |
|---|---|---|
| 历史迁移方言不一致 | 采用独立 PostgreSQL 基线，不直接重放 | 批准基线目录与生成方式 |
| 测试误写源 SQLite | 源快照只读、独立 URL、测试前连接守卫 | 批准测试库后实施守卫 |
| 数据丢失或重复 | 主键/唯一键/聚合/关联四类核对 | 批准数据装载脚本前复核 |
| 连接串或权限泄露 | 仅受控环境注入，不进仓库或日志 | 创建账号与授予最小权限 |
| 回滚不可行 | 保留 SQLite 快照与当前应用版本，先演练 | 任何生产切换前单独批准 |
