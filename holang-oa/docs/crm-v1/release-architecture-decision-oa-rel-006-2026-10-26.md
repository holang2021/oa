# OA-REL-006：发布架构收敛设计

日期：2026-10-26
状态：设计完成；实施待批准。
范围：只解决发布架构、分支、构建目录、健康检查与回滚的一致性；不部署、不改工作流、不改 Docker、不连接服务器。

## 已证实的冲突

- 当前候选代码位于 `system-build`，而现有 Actions 监听 `main`；两者不是同一版本。
- 实际前端位于 `packages/oa`，Docker 编排仍引用不存在的 `./frontend`。
- Docker/PostgreSQL、现有 SQLite/PM2/TAT 脚本与健康检查配置并非同一条可验证路径。
- 当前没有对候选版本完成的部署、备份恢复或回滚证据。

## 推荐决策

在 PostgreSQL 测试迁移、完整回归与预发布演练通过前，采用**现有 PM2/TAT 运行形态作为唯一候选发布路径**，并以 `system-build` 的经验证发布候选为唯一输入。Docker Compose 不进入本次上线链路；其路径、数据库与配置问题另行修复和验收后才可作为替代方案。

推荐并不等于实施授权。发布分支合并、Actions 改造、服务器变更与任何生产部署均须分别批准。

## 实施前必须完成的收敛项

1. 定义发布候选规则：只有通过 `OA-ENV-004`、`OA-CRM-002`、`OA-DB-001` 测试门禁的固定 Git SHA 可进入预发布。
2. 定义单一路径：候选 SHA → 可复现后端/前端构建 → 预发布 PM2/TAT 部署 → 健康检查 → 业务烟雾 → 回滚演练。
3. 对齐路径与探针：前端产物目录、后端端口、健康检查 URL、日志位置和退出判定必须由同一份发布清单声明。
4. 对齐数据库策略：预发布先使用已批准的 PostgreSQL 测试方案；不得让 SQLite 生产脚本和 PostgreSQL 发布脚本在同一次发布中混用。
5. 生成回滚包：上一可用应用版本、经校验的数据备份、恢复步骤和验证证据必须成套存在。

## 验收标准

- 对同一候选 SHA，可在隔离环境重复构建并得到可追溯产物。
- 发布、健康检查、业务烟雾与回滚均引用同一条发布清单。
- 回滚演练恢复到上一应用版本与已验证数据状态，且不依赖临时个人目录。
- Docker 路径在未通过独立验收前，不被误用作本次上线通道。

## 下一动作与审批点

待 `OA-ENV-004` 恢复验证环境后，创建不触及生产的预发布发布清单草案。改动 GitHub Actions、PM2/TAT、Docker、服务器、DNS、端口或生产配置前，主线会提交精确变更和回滚方式，等待明确批准。
