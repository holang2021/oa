# OA-SEC-007：生产配置与敏感值治理方案

日期：2026-10-26
状态：治理方案完成；任何轮换或配置修改待批准。
范围：只记录处理原则和上线门禁。本文不包含、不复述任何实际敏感值。

## 风险判定

已提交的部署配置中发现敏感配置值。按已暴露处理：不得继续作为生产凭据使用，也不得复制到日志、文档、测试夹具或新配置文件。默认管理员凭据同样不得进入公网或生产环境。

## 治理顺序

1. 建立敏感项清单，仅记录字段类别、责任人、轮换状态和验证时间，不记录值。
2. 在受控密钥存储或部署平台秘密变量中创建新值；最小权限、按环境隔离、禁止写回仓库。
3. 轮换已暴露值和默认管理员凭据，验证旧值失效；轮换顺序须确保业务可回滚。
4. 将运行配置改为只读取受控环境注入；仓库仅保留无真实值的示例文件。
5. 审计当前分支与历史泄露范围，制定必要的访问控制与后续清理策略；历史重写或删除须单独批准。
6. 在预发布验证登录、外部接口、健康检查与回滚，不输出任何秘密。

## 上线门禁

- 所有发现的敏感类别均已轮换或由责任人书面接受风险。
- 生产环境不使用默认管理员凭据，且已建立首次管理员安全交接流程。
- 部署日志、CI 日志、错误回显和诊断包均通过脱敏检查。
- 密钥权限与轮换日期可审计，且生产、预发布、开发环境互相隔离。

## 审批边界

创建或轮换凭据、修改 CI/CD 秘密变量、服务器配置、用户权限或 Git 历史均是高风险动作，必须在实施前由用户明确批准。主线可在批准前继续维护清单和验收设计，但不得读取、显示或写入真实值。
