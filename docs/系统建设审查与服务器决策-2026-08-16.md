## 三、压迫式审核（第一性原理连问）

**Q1：我们为什么建这套系统？**
→ 统一客户池 + 业务在线化 + 内销/外销绝对隔离。现状：客户/订单已在线，但市场获客闭环未接、伙伴云未迁入 → **解决了"记录"，没解决"增长"**。

**Q2：服务器不续会怎样？**
→ 全丢。所以"续"是默认。但更尖锐的是：**不续才丢，磁盘坏也丢，被回收也丢**——我们没有任何容灾。续费只是买了一个月的缓刑，没解决根本脆弱性。

**Q3：架构对吗？**
→ 错。"AI+WorkBuddy+OA+WEB" 全堆一台 4G 机 = 错误耦合 + 爆炸半径最大化。任一组件故障/被攻击/资源耗尽，全盘陪葬。正确做法：至少 DB 独立 + 定期快照/COS 备份；中长期按"AI / OA / 官网"分实例。

**Q4：专家团在干嘛？是不是空转？**
→ 已建 25+ 专家/技能，但不少是"能力资产"而非"在干活的人"。飞书方案 A 卡了多天、企微角色矩阵久悬未决 → **专家建了，但没映射到部门、没认领具体落地任务**。这正是这次开会要解决的：让每个部门认领自己的系统建设任务。

**Q5：我们是不是在"为建系统而建系统"？**
→ 有此苗头。OA 模块很多，但刘总最看重的**获客(GEO)闭环**反而是空白。建议：下一阶段重心从"内部记录系统"转向"获客→转化→记录"全链路。
