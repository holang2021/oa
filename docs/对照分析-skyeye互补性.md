# dromara/skyeye vs HOLANG 内部管理系统 — 互补性分析

> 分析日期：2026-07-16 | 参照：skyeye GitHub 主干 README + 我们 `docs/` 内架构规划与对照分析
> 结论先行：**skyeye 不宜"接入"，但极值得"借脑"——它是我们 Phase 2/3 模块设计与"轻量低代码"路线的现成参考架构。**

---

## 一、技术栈对比（核心差异）

| 维度 | skyeye | HOLANG 我们 | 影响 |
|------|--------|------------|------|
| 后端语言 | Java + Spring Cloud Alibaba 微服务 | Node/Express（wecom-callback）+ 本地 JSON/飞书 Bitable/SQLite | **栈不兼容**，无法源码级融合 |
| 中间件 | Nacos / RocketMQ / Sentinel / XXL-Job / Redis / MySQL | 仅 Node + 轻量 DB（Phase 3+ 才上自建库） | 跑 skyeye 需整套 Java 基础设施 |
| 前端 | Vue3 + Vite5 + Ant Design Vue4（PC）+ uni-app（移动） | React + Vite + Tailwind + Radix/shadcn（admin）；React18（crm） | 前端栈也不同 |
| 移动端 | APP / 小程序 / H5 一套代码 | 仅企微工作台 H5 + PC 浏览器 | **我们缺原生移动端** |
| 低代码 | 5 大可视化设计器（表单/布局/流程/编码/打印），零 Java 代码 | 全手写 React 组件 | **这是最大互补点** |
| 多租户 | 原生 SaaS 多租户 | 单租户（内部） | 我们不需要，非互补 |
| 身份 | 通用账号体系 | **企微 OAuth 原生**（无密码）+ 通讯录同步 + 朗工 AI | 我们的独有价值 |
| 开源完整度 | 主干开源不全，全量业务源码需付费会员 | 100% 自研自持 | 直接"用"它受限 |

> **关键判断**：技术栈与身份模型根本不同，且 skyeye 全量源码收费 → 把它当"可运行系统接进来"不现实、也不经济。正确姿势是**把它当制造业全链路系统的"设计参考书"**。

## 三、skyeye 能补我们的（重点借力 5 处）

1. **轻量低代码表单/打印设计器（最高优先级）**
   我们每加一个模块都手写 React 表单，这正是 `对照分析` 里 9 个看板 + 多张单据"全缺/待建"的根因——产能被重复造表单吃掉。skyeye 证明"表单+打印可视化设计器"可让业务表单快速上线。
   → 对我们最现实的互补：**做一个内部简易表单/打印设计器**，作为"全依赖伙伴云"和"全手写"之间的中间态，直接加速 Phase 2（报价单/合同/发货单）。

2. **MES + WMS 深度模块设计（Phase 2/3 直接参考）**
   一物一码、条形码、报工、质检、盘点——这些是制造业刚需，我们目前只有占位。skyeye 的模块拆分是现成蓝图。

3. **报表/BI 看板设计**
   9 个分析看板缺失是管理层最关心的红色差距。skyeye 各模块报表的维度设计可直接借鉴。

4. **移动端策略（扫码/报工/盘点）**
   工厂现场必然要扫码、移动报工、移动盘点。skyeye 用 uni-app 一套出 APP/小程序/H5 证明移动端必要性。我们应补 **企微小程序** 作为现场入口（与我们企微原生身份天然契合）。

5. **工作流节点完备性校验**
   用 Activiti 的 BPMN 节点类型（会签/或签/并行/子流程/定时/条件分支）反向校验我们自建审批引擎是否遗漏关键节点。

---

## 四、我们领先 / skyeye 给不了（守住不丢）

- **企微原生**：OAuth 无密码登录、通讯录同步、工作台 H5、朗工 AI 对话入口——skyeye 是通用 SaaS，完全没有。
- **AI 原生（Phase 5）**：RAG 知识库 + AI 日报/周报/月报 + 智能问答，skyeye 是传统系统，无 AI。
- **自持可控、零授权费**：我们 100% 自研，贴合 HOLANG 工业气体设备业务；skyeye 全量源码收费。
- **轻运维**：Node/React 轻量栈，小团队可维护；skyeye 需整套 Java 微服务基础设施。
- **已对齐真实业务蓝图**：我们的模块映射自伙伴云蓝本与 Excel 规划，skyeye 是通用模板。

## 六、风险与边界

- 🔴 **开源主干不全**：GitHub/Gitee 主干不含全量业务代码，全量需付费会员。只能"借设计"，不能直接"拿代码跑"。
- 🔴 **栈不兼容**：Java 微服务栈与我们的 Node/React 栈无法融合，强行引入等于并行维护两套重基础设施，小团队不可承受。
- 🟡 **勿本末倒置**：我们的差异化在"企微原生 + AI"，低代码/MES 只是补能力短板，不要为了对齐 skyeye 而偏离 AI 主线。
- 🟡 **多租户/商城/EHR 暂不必跟**：内部单公司、工业设备主业，这些不是当前优先级。

---

## 七、一句话总结

> skyeye 是"制造业全链路系统该怎么长"的成熟参考答案；我们不必长成它，但应**抄它的"表单设计器 + MES/WMS 模块 + 报表维度 + 移动端"这四块短板，同时死守"企微原生 + AI"这两块它永远给不了我们的长板**。
