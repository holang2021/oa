## 二、各方「日常必须看的数据字段 + 频率 + 当前来源」

### 2.1 销售视角（holang-gas-sales 贡献）

| 字段 | 含义 | 频率 | 当前来源 |
|---|---|---|---|
| 今日待跟进客户 | 需今天回访客户 | 日 | customers.nextFollowAt / overdueFollow |
| 今日待跟进线索 | 分配待处理线索 | 日 | leads.nextFollowAt / followOverdue |
| 待回款订单 | 逾期/待回款金额 | 日 | orders.unpaidAmount + payments.plannedDate |
| 待发货申请 | 已付款待发货 | 日 | deliveries.flowStatus / orders.deliveryDate |
| 今日新增线索/客户 | 新进入池 | 日 | leads.createdAt / customers.createdAt |
| 团队当日跟进量 | 下属活动量 | 日 | follow_ups.createdAt(user) |
| 商机漏斗 | 各阶段金额/赢率 | 周 | opportunities.stage / winProbability / expectedAmount |
| 报价状态 | 在途报价与转化 | 周 | quotes.status / totalAmount |
| 本周回款进度 | 实收 vs 计划 | 周 | payments.receivedDate / orders.collectedAmount |
| 内外销分布 | 运营结构占比 | 周 | customers.businessLine / salesType |
| 月业绩达成率 | 目标 vs 实际 | 月 | sales_targets.targetAmount vs orders.amount |
| 客户账期应收 | 欠款/信用敞口 | 月 | customers.paidAmount / unpaidAmount |
| 毛利率 | 订单盈利 | 月 | orders.grossMargin / totalCost |
| 国家分布 | 外销市场版图 | 月 | customers.country |
| 丢单/无效线索 | 流失归因 | 月 | leads.invalidReason / status |

**销售侧补不上的（需后续建设）**：销售活动量（通话/邮件/拜访次数，OA 无字段）、外销汇兑损益计算、加权销售预测/报价转单率/渠道 ROI 聚合报表、客户健康度与复购预警、竞品价格情报。

### 2.2 市场/增长视角（holang-brand-growth 贡献）

| 字段 | 含义 | 频率 | 当前来源 | 理想来源 |
|---|---|---|---|---|
| 新增线索数 | 当日新进 Lead | 日 | Lead.createdAt | OA 已有需规整 |
| 线索来源分布 | 各 source 占比 | 日 | Lead.source | OA 有但自由文本，需枚举标准化 |
| 渠道报备新增 | 经销商报备数 | 日 | DealerReport.createdAt | OA 已有 |
| AI 搜索可见性 | 品牌被 AI 引用次数/排名 | 日 | OA无 | GEO 看板 |
| 官网流量与询盘 | 访客/表单/WhatsApp | 日 | OA无 | GA4 + 官网表单 |
| 线索→客户转化率 | Lead 转 Customer | 周 | Lead→Customer 跨表 | OA 可算需关联 |
| 来源有效/无效率 | 各 source 无效率 | 周 | Lead.source+status | OA 已有 |
| 经销商报备转化 | 报备最终成交 | 周 | DealerReport+Customer | OA 可算 |
| 关键词/AI 引用排名 | 核心词排名、被引用率 | 周 | OA无 | Semrush + GEO 看板 |
| 内容发布与互动 | 博客/白皮书阅读转发 | 周 | OA无 | CMS/内容平台 |

| 获客成本 CAC(分渠道) | 单线索/客户成本 | 月 | OA无 | 广告费/展位费台账 |

| 赢单来源归因 | Order 回溯 Customer.source | 月 | Customer.source+Order | OA 部分已有 |
| 品牌词搜索量/AI 提及率 | 月度声量 | 月 | OA无 | GA4 + GEO 看板 |
| 国家市场渗透 | 各国客户数/金额 | 月 | Customer.country+Order.amount | OA 已有 |

**市场侧必须新建的三大数据域**：① 渠道归因与 CAC/活动 ROI（OA 仅零散 source 文本）；② GEO/内容指标域（AI 可见性/关键词/互动，OA 全无）；③ 线索质量量化域（需统一来源枚举+渠道标签+转化漏斗口径）。

### 2.3 建设侧映射（OA 数据模型 → CRM 草稿，见第五节归属校正）

- **复用清单（A）**：customers/contacts（统一客户池）、users/wecom_departments（销售组织）、leads、opportunities、quotes/quote_items、orders/order_items、payments、invoices、deliveries、contracts/contract_entities、follow_ups、sales_targets、reports、dealer_reports。
- **缺口（B 改造复用）**：products（表在=0，需填充设备目录）、opportunities.stage（设计完备未启用）、leads（空，需导入+补 source）。
- **缺口（C 新建）**：售后/保修/维修（OA 无表）、市场归因/CAC/GEO（OA 无表）。

## 三、复用闸门判定（A/B/C 显式）

| 数据域 / 能力 | 判定 | 理由 |
|---|---|---|
| 客户池 customers/contacts | **A 直接复用** | OA 已有 394 条真实数据，零重建 |
| 订单/回款/开票/发货/合同 | **A 直接复用** | orders=283、payments=458 已有数据 |
| 报价 quotes/quote_items | **A 直接复用** | 表+流程已建 |
| 跟进 follow_ups、目标 sales_targets、报告 reports、经销商 dealer_reports | **A 直接复用** | 表已建 |
| 线索 leads | **A 表 + B 填充** | 表存在数据=0，需导入并补 source 枚举 |
| 商机 opportunities | **A 表 + B 启用** | 表存在未使用，需启用 stage 流程 |
| 产品 products | **B 改造复用** | 表存在=0，填充设备产品库即可，不新建 |
| 销售活动量/预测聚合/客户健康度 | **C 新建(报表层)** | OA 有原始字段缺聚合，属 Phase 2 报表能力 |
| 市场归因/CAC/GEO/内容指标 | **C 新建** | OA 完全无对应表，必须新建数据域 |
| 售后/保修/维修 | **C 新建** | OA 无任何售后表（见第四节） |

**闸门结论**：约 80% 销售 CRM 能力可被 OA 现有数据 **A/B 覆盖**，仅售后 + 市场归因两块需 **C 新建**，且均排 Phase 2，严守「OA 已有数据不重建」。

## 四、售后专家是否新建 — 治理判定

**问题**：售后专家当前无专属实体，是否新建？

**判定：Phase 1 不新建，走 B 改造复用。**
- 售后是真实业务域，但 11 人团队售后量小，且 **OA 尚无任何售后数据模型**（无 warranty/维修工单/回访表），专家无可依托的数据底座。
- 按「禁止遇缺即建」：先用 **holang-gas-sales（销售专家）扩展售后视图**承接 Phase 1 的售后查询（改造复用 B），不单独建专家。
- **触发 C（新建独立售后专家）的条件**（满足任一即提《能力建设申请》）：
  1. service_tickets/warranties 等售后数据域已在 Phase 2 落地且有稳定数据；
  2. 售后工单月量 > 20 单，销售专家难以兼覆盖；
  3. 出现独立售后 SLA/质保追责诉求。

**售后数据域（C 新建，Phase 2）**：由 holang-tech-lead 在 Phase 2 提《能力建设申请》，新建 service_tickets（维修工单）、warranties（保修）、after_sales_visits（回访），经 customerId/orderId 挂接统一客户池。该申请不在本次提交（Phase 1 不触发）。

## 五、建设侧归属校正（重要）

刘总指令点名 **de-arch-assistant（数字员工架构师）** 承接建设侧，但按 2026-07-21 已落地角色边界：
- **holang-tech-lead（信息化总监）** = 公司真实 IT 系统（CRM/ERP/人事/仓储/网站+网络）规划、技术蓝图、代码规则、验收核对。
- **de-arch-assistant（数字员工架构师）** = 仅管 WorkBuddy AI 数字员工体系治理，输出建议不执行。

**OA 数据模型 → CRM 蓝图属 IT 系统规划，正式归属 holang-tech-lead。** 本草稿由建设侧代产出，建议刘总拍板时一并确认归属移交，避免职责错位。de-arch-assistant 可在 Phase 2 售后专家新建时承接「AI 数字员工」设计部分。

## 六、报刘总拍板事项（决策清单）

1. **复用优先方案是否批准**：A/B 覆盖约 80% 能力，仅售后+市场归因 C 新建（Phase 2）。
2. **建设侧归属确认**：OA→CRM 蓝图正式移交 holang-tech-lead（非 de-arch-assistant）。
3. **售后专家 Phase 1 不建、Phase 2 触发条件确认**：是否同意「先扩展销售专家承接，达标再独立建」。
4. **Phase 1 范围确认**：填充 products/leads/opportunities + 跑通 线索→…→合同 全链路（工作量：中）。
5. **Phase 2 优先级**：售后数据域 vs 市场归因域，哪个先建（建议市场归因先于售后，因获客是当下重心）。
