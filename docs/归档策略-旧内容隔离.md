# 归档策略 · 旧内容隔离（2026-07-16）

> 背景：方案 A 确认"全部归 OA"后，需把 OA 统一基线确定前的旧内容、旧版本、遗留脚本做彻底梳理与隔离。本策略与 `archive/` 目录配套，是执行层面的正式记录。

## 决策要点
1. **所有旧内容物理隔离到 `archive/`**，与活跃系统分离；仅隔离、不删除。
2. **分类隔离**：`holang-crm/`（旧前端）、`legacy-root/`（crm 数据/Python 脚本/伙伴数据/日志/杂项）、`sensitive-quarantine/`（疑似凭据，文件留原位不搬）。
3. **留存期评估结论**：普通遗留 **90 天**（到期 **2026-10-14**），且不早于 OA 新前端（holang-admin）正式上线日；敏感项不设自动到期，须人工确认。
4. **到期处理**：2026-10-14 起生成《待删除候选清单》→ 你确认 → 分批（≤10/批、先备份后删、走回收站）删除。敏感项单独人工流程。

## 不隔离、保留的项（重要边界）
- 生产系统：`holang-oa`（后端 + 394 客户数据 + 旧前端）、`holang-oa.db` 及备份、**永不删**。
- 活跃基础设施：`wecom-callback/`，保留。
- OA 基线：`holang-admin/`（holang-oa-frontend），保留发展。
- 业务蓝本：`quotation_*.json`（4 份）被 OA 表单引擎引用，留原位对齐 OA。
- 疑似凭据：`oa_login.json` 按既有红线**不读/不搬/不删**，留原位等人工确认。
