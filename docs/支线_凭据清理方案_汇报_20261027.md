## 三、高危暴露点判定
- **oa_login.json：无直接打印。** 两个 `.mjs` 仅把凭据放进对本地 OA（`localhost:3001/5173`）的请求体，控制台只打印 `status/code`，**不回显 PASS/TOKEN**。低风险。
- **github_token.txt：存在高危暴露点。**
  - 高危 `push_repo.bat:26`：PAT 被拼进 `git` 命令行的 URL（`https://%TOKEN%@github.com/...`），令牌出现在 git 进程参数（argv），可被进程监控/审计工具捕获；且 push 失败回显可能把带令牌的 URL 写入 `push_result.txt`（已被 gitignore 覆盖，但留存磁盘）。
  - 轻微 `push_repo.bat:16`：`echo %TOKEN% | findstr` 校验前缀——令牌经管道传入不显示屏幕，但串出现在 cmd 内部命令命令行，有被命令行审计捕获的轻微风险。
  - 改进方向（见方案第 4 步）：避免把令牌写进命令行/日志；优先用 `gh` CLI 或 git credential helper 托管，或在 `.bat` 内改存环境变量、去掉 `echo %TOKEN%` 校验。

## 四、分步清理方案
1. **人工前置（必做，Agent 不碰原值）**：在 GitHub 后台 Revoke/轮换当前 PAT 取得新值；在 OA 后台重置 `oa_login.json` 对应用户密码/会话取得新凭据。
2. **删明文**：本地删除根目录 `github_token.txt`、`oa_login.json`。
3. **新建 `.env`**（根目录，已被 `.gitignore:11` 覆盖）：
   ```
   GITHUB_TOKEN=__NEW_PAT_FROM_GITHUB__
   OA_USER=__OA_USERNAME__
   OA_PASS=__NEW_OA_PASSWORD__
   ```
4. **改 `push_repo.bat`**：用 `for /f` 从 `.env` 解析 `GITHUB_TOKEN`；去掉 `echo %TOKEN%` 前缀校验，改用 `if "%GITHUB_TOKEN:~0,4%"=="ghp_"` 判断（不回显令牌）；push 时仍用 insteadOf 注入。可选优化：改调 `gh` 或配置 git credential helper，避免令牌进入 argv/日志。
5. **改 `probe_customers.mjs` / `verify_phase1.mjs`**：替换 `resolve(__dirname,'../../oa_login.json')` 为从根目录 `.env` 读 `OA_USER`/`OA_PASS`（Node 侧用 `dotenv` 或手读 `.env`），不再引用 `oa_login.json`。
6. **验证**：
   - `git check-ignore .env github_token.txt oa_login.json` → 均应为 `true`（已实测：`.env`→`.gitignore:11`、`github_token.txt`→`:91`、`oa_login.json`→`:10`）。
   - 确认两明文文件已从磁盘删除，且全仓不再有脚本以文件名引用它们。
7. **红线复核**：全程不读/不打印原凭据明文；新值由用户写入 `.env`，Agent 仅改引用代码、不接触真实值。
