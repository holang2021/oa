## 一、目标与边界（第一性原理）

**真正目标**：让非技术的销售/管理员，把**自己真实的 Excel/Word 报价单模板**上传进 OA，
把模板里的「可变格」绑定到系统数据字段，点一下就能**预览/打印出和客户手里一模一样的报价单**。
减少重复录入、保证 OA 出的单子和公司现有模板完全一致。

**边界（明确不做什么）**
- 本立项 **Phase 1 只做 Quote（报价）**，因为 Quote 的数据当前已存在于前端表单 state。
- 合同 / PI / 订单的对应数据**尚未建设**，其 dataKey 来源不存在 → 本阶段**不接**，留 Phase 2。
- Phase 1 **不碰后端 / Prisma / 数据库 / 任何 API**（与现有打印模板一致：纯前端 + localStorage）。
- 本引擎是**独立功能**，不回写、不改造当前 Quote V1 手搓预览；验证通过后，未来再决定用引擎替代手搓预览。

## 四、关键设计决策：xlsx 即版式 + 红字格=变量

**用户真实模板已自带约定**：分析 `HOLANG氮气发生器报价单模板.xlsx` 确认——
模板里所有**红色字体单元格 = 可变录入项**（报价编号、客户名/联系人/邮箱/电话/主题、各项型号/规格/数量/单价/总价、备注）。
→ **绑定约定天然存在，无需另立标记规范**：解析时自动识别红字格，预列为「可绑定变量」。

**渲染策略（保真优先）**：不把 xlsx 强行转成现有 `fields` 字段模型（会丢合并格/红字样式/列宽），
而是**保留 xlsx 原版式**渲染：解析出的合并单元格、列宽、字体、填充原样复现，
仅把「绑定格」的值替换为 OA 实时数据。这与用户「严格参考这个格式」诉求完全契合，
且比重建字段模型**工作量更小、还原度更高**。

## 五、架构与模块边界（规划）

```
packages/oa/src/
├─ services/templateImport.ts      【新增】SheetJS 解析 xlsx → ParsedTemplate
├─ services/printTemplateStore.ts 【扩展】PrintTemplate 增加 bindings: CellBinding[]
├─ components/XlsxTemplatePreview.tsx 【新增】按 ParsedTemplate 保真渲染 + 绑定值替换
├─ pages/PrintTemplates.tsx       【扩展】编辑器加「上传 Excel」+「绑定模式」
└─ pages/QuoteForm.tsx            【不动，Phase1 验证期】验证通过后未来再切换
```

**新增数据契约**
```ts
interface ParsedCell {
  ref: string            // 如 "H17"
  value: string
  isVariable: boolean    // 红字格=true
  merge?: { row: number; col: number; rowspan: number; colspan: number }
  colWidth: number; rowHeight: number
  font?: { bold?: boolean; color?: string; size?: number }
  fill?: string
}
interface CellBinding { cellRef: string; dataKey: string; transform?: 'item' | 'sum' | 'none' }
interface PrintTemplate {
  // ...既有字段保留...
  source: 'fields' | 'xlsx'     // 新增：来源
  xlsxBase64?: string           // 新增：原模板（用于保真渲染）
  bindings: CellBinding[]       // 新增：红字格→数据字段映射
}
```

**dataKey 词表（Quote Phase 1）**
- 表头：`quotationNo` `quotationDate` `validDays`
- 客户：`customerName` `customerContact` `customerEmail` `customerPhone` `quoteSubject`
- 我方：`companyContact` `companyEmail` `companyPhone`
- 行项：`items[].name` `items[].model` `items[].spec` `items[].qty` `items[].unitPrice` `items[].total`
- 汇总：`totalAmount` `chineseAmount`
- 备注：`remarks[]`（编号列表）`terms[]`

> 行项为多行重复块：绑定 `items[].name` 等时，引擎按行项数量自动向下复制块并逐行填值（对齐模板「纵向合并项号 + 多行规格」结构）。

## 六、用户操作流程（销售视角）

1. 进「打印模板」页 → 点某 Quote 模板「编辑」→ 点「上传 Excel 模板」选真实 xlsx。
2. 系统解析 → 自动标出所有红字格（变量）→ 进入「绑定模式」。
3. 逐个点红字格 → 从下拉选对应 dataKey（如 H17→`items[].unitPrice`）→ 保存。
4. 回 Quote 表单 → 点「预览/打印」→ 选该模板 → 看到**与客户手里一模一样**的报价单。
5. 导出 PDF / 打印，版式与模板一致。

## 八、风险与遗留（压迫式审核）

1. **公式单元格**：模板 H17=`=F17*G17`、H32=`=SUM(...)` 是公式。引擎**不求值 Excel 公式**，
   改为用绑定 `transform`：`items[].total`=单价×数量、`totalAmount`=各项求和，由 OA 数据计算后填入。→ 已纳入设计。
2. **图片/Logo**：xlsx 内 logo 可能是嵌入图片，需提取并定位；或允许用 URL 覆盖（当前 Quote V1 已用 `/HOLANG_Logo_Official.png`）。→ 列为 Phase 1 细化项。
3. **多工作表 / 打印区域**：取打印区域或首个工作表。→ 实现时确认。
4. **合同/PI/订单数据未建**：引擎 dataKey 机制已预留，但那些来源不存在 → **Phase 2 再做**，本阶段不接。
5. **与手搓预览的关系**：本引擎验证通过前，Quote V1 手搓预览继续存在；通过后由刘总决定是否切换。→ 不强制替换。
