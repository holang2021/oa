## 一、第一性原理：OA「真正投入使用」的最小定义

**根本目标**：真实员工每天登录 OA 做真实业务（客户跟进、报价、订单查看），业务在线化闭环。
**最小可行（MVP）**：**一小撮试点用户（销售负责人 + 关键销售 5–8 人）每天用** 客户 + 跟进 + 报价 + 订单查看——**不是全公司铺开**。

**反推上线的最小可行动作** = 让上面成立：①有人（账号供给）②敢用（安全闸门）③有权（角色矩阵）④像在用（真实管线数据）。

---

## 二、阻碍上线的根本障碍（逐层，非次要事项）

1. **没人用**：账号供给断链——企微同步未持久化（0 部门）+ 仅 1 真实员工账号 → 无用户基数。
2. **不敢用**：默认密码 `admin/admin123` 仍在生产 → 安全风险，不能放真实员工。
3. **不会用**：角色矩阵未拍板 → 给不了正确权限；无培训/上线计划。
4. **不像在用**：商机/报价/线索为空 → 系统只记历史，未成日常工具，试点也无数据可操作。

---

## 三、压迫式审核（把自身结论当嫌疑人重查）

- **「通讯录同步已闭环」是伪结论**：生产库 0 部门 / 3 用户，与"8/4 写 10 成员"记忆矛盾 → **不能信"已通"，必须重做并复测持久化**。
- **「394 客户」含金量为低**：354 无来源 = 批量灌入，非业务沉淀；上线 ≠ 数据多。
- **我此前把续费/备份当主线是错位**：用户本次聚焦 OA 正确——真正卡上线的是"没人用"。
- **MVP 不能是全公司**：应是试点小组每日真实使用，避免"全员上线"虚指标。

## 五、最短周期：从停滞→执行的头三步

1. **👤你今天拍板角色矩阵（默认 B）+ 确认改密** → 解锁安全闸门（唯一不可代理）。
2. **🤖我重做企微同步并复测持久化**（不再信"已闭环"），手动补试点账号 → 解决"没人用"。
3. **🔧销售专家提供"当前在跟真实单"清单** → 🤖灌入商机/报价，让系统首日就有真数据。

## 六、硬性验收总闸（8/23 前必须全绿）

- 🟢 **安全**：默认密码改掉 + JWT 强随机
- 🟢 **有人**：试点 ≥5 真实账号 + 企微部门同步持久化（复测 >0）
- 🟢 **有权**：角色矩阵落地 + 权限按业务域隔离
- 🟢 **有数**：商机/报价含真实在跟单（非空）
- 🟢 **能用**：试点每人独立完成「看客户→写跟进→建报价」
