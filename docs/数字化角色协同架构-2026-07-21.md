## 一、架构总览（流程）

```
老板（刘总）：诉求源 · 最终验收
        │ 诉求/目标（下）   汇报/对齐（上）
        ▼
数字负责人（我）：跨域治理中枢 · 调度 / 验收
        ├─路由→ 信息化总监（holang-tech-lead，建设落地负责人，2026-07-22 正式注册）：公司 IT 系统 + 选型对标
        └─路由→ 数字员工架构师（de-arch-assistant，已有）：AI 员工体系
                    │ 治理建议回流
信息化总监 ──技术蓝图/规则──┐
                           ▼
                    执行层（落地）
              CodeBuddy 写码 · 人类技术方 部署上线
                           │ 验收结果（虚线回流）
                           ▼
                    数字负责人（验收）→ 老板
```

## 二、三者职责边界

| 角色 | 管什么 | 不管什么 | 状态 |
|------|--------|----------|------|
| **数字负责人（我）** | 跨域治理中枢：发现问题、判断类型(A-F)、调度已有能力、跨域协调、验收追踪、OPS 治理 | 不写码、不部署、不下服务器指令、不碰单域技术细节 | 当前会话角色（已生效） |
| **信息化总监（建设落地负责人）** `holang-tech-lead` | 公司真实 IT 系统：CRM/ERP/人事/仓储/网站+网络；技术蓝图、代码规则、技术 review、验收核对；**建设落地 accountability**（规划会强制到场、驱动排期、review、验收签字）；**选型对标**（建设前调研并对标询盘云/成熟 ERP 等外部系统） | 不部署、不直接写生产代码（交 CodeBuddy/人类技术方）；对落地负责 ≠ 亲手写码 | **2026-07-22 正式创建并注册 v1.0.0**（升级为建落地负责人） |
| **数字员工架构师** `de-arch-assistant` | WorkBuddy 数字员工（AI 员工）体系治理：判断 AI 员工能力的新增/拆分/合并/暂停/升级，**仅输出建议** | 不自动创建/发布/删除 Agent、不碰公司业务 IT 系统 | 已存在（README 仍 TODO 占位） |

## 三、协作流程

1. **老板提诉求** → 数字负责人接，先判问题类型（A 业务 / B 流程 / C 系统 / D 数据 / E 知识 / F 能力）
2. **路由**：
   - 涉及公司 IT 系统建设（CRM/ERP/网络/代码）→ 路由**信息化总监**出技术蓝图、规则、review
   - 涉及 AI 员工体系调整（要新建/拆分某个数字员工）→ 路由**数字员工架构师**出治理建议
3. **信息化总监先跑双闸门** → ① 内部复用闸门（六层优先级，OA 已有不重建）；② 外部选型对标（调研询盘云/成熟 ERP 等，输出「可借鉴 / 可复用 / 自研」三栏结论，沉淀至「选型对标知识库」）。两闸门未跑不得出蓝图。
4. **信息化总监出蓝图并会签** → 输出技术蓝图/代码规则；作为**建设落地负责人**在验收栏会签（落地角色缺席时方案只能称「规划草稿（待落地方会签）」）→ 交**执行层**（CodeBuddy 写码 + 人类技术方部署）。
5. **执行层落地** → 结果回流**数字负责人**做验收核对。
6. **数字负责人验收通过** → 汇报老板，闭环。

## 四、与执行层的关系（关键，避免混淆）

| 层 | 是什么 | 谁管 |
|----|--------|------|
| 治理层 | 数字负责人 + 两个专家（判断/规划/治理） | WorkBuddy 专家体系 |
| 执行层 | CodeBuddy（写码工具）+ 人类技术方（部署/审） | 刘总自己管 CodeBuddy；人类技术方另行指派 |

- **CodeBuddy ≠ WorkBuddy 专家**，是独立产品（腾讯 AI 编程助手），刘总自己管理，读不到本会话实时上下文
- **专家都不写码不部署**：这是角色边界 + 服务器禁令双重锁死
- 专家的价值是让执行层的"需求"足够精确（路径/接口/规则/验收写死），减少来回纠偏

## 五、关键结论

- ❌ **不改造 `de-arch-assistant` 当信息化总监**：两者职责错配（AI 员工治理 vs 公司 IT 治理），且 de-arch 自身也是空壳，改造不比新建快、反而更乱
- ✅ **新建 `holang-tech-lead`（信息化总监·建设落地负责人）**：实际于 **2026-07-22** 正式创建 plugin.json + agent md 并注册（v1.0.0，含建设落地 accountability 与选型对标职责）；此前 07-21 的「已注册」记录未真正落地，已更正。
- ✅ **三者各司其职**：数字负责人跨域调度，信息化总监管公司 IT，数字员工架构师管 AI 员工；未来要统一治理数字员工时由我路由调用 de-arch-assistant
