## 五、需逐条确认的问题（你逐条回，或从 Q1 起）

### 【A 客户与销售流程真实形态】
- **Q1** 客户分「内销 / 外销」两个独立频道管，还是**统一客户池 + 标签区分**？ → ✅ **已决（2026-07-20，最终裁定）：双系统**——统一客户资产池（主数据一份，不重复、不丢客户）+ 内销/外销**各自独立一套运营系统**（线索/商机/报价/订单/回款/售后彻底分开跑）。即"统一池 + 双系统"，非单系统内双模块。影响：客户主数据只建一份；但运营模块（询盘/商机/跟进/报价/订单/回款/售后）内销外销各一套，工作量约为单系统的 2 倍；数据模型需区分"统一客户主数据"与"按渠道隔离的运营数据"两层，见 Q10 修订影响
- **Q2** 实际有没有「线索（Lead）」这个阶段？还是客户一进来就是确定跟进对象？ → ✅ **已决（2026-07-20）：需要线索阶段**（刘总确认获客后有独立「线索→转化」环节，库里 leads=0 仅因未建，需补线索管理）
- **Q3** 「商机（Opportunity）」在你们业务里对应什么？一台设备的采购意向，还是更大的项目？商机阶段流转（拜访→技术交流→谈判→签单）这套**真走吗**？ → ✅ **已决（2026-07-20）：简化商机阶段**（商机=单台/单笔设备意向，阶段只分跟进中/报价中/成交/丢单几档，不走7步重流程，后续按需扩展）
- **Q4** 销售跟进（SFA）：要系统在里记「跟进记录 / 跟进计划」，还是**只管结果（订单/回款）**、过程靠企微/口头？ → ✅ **已决（2026-07-20）：系统记跟进 + 计划**（配合 Q2/Q3 形成销售过程闭环，管理员可随时看进度）

### 【B 报价与产品】
- **Q5** 报价现在实际怎么出？销售**手填 Excel 模板**，还是想收进系统自动算？报价和某个客户/商机关联紧吗？ → ✅ **已决（2026-07-20）：系统生成 + Excel 导出**（过渡期双轨，系统里做报价、保留 Excel 导出/导入，逐步迁移；关联客户/商机）
- **Q6** 非标设备每台配置不同——「基于产品库选品自动算价」**能做吗**？还是每次都手工定制、产品库只作目录参考？ → ✅ **已决（2026-07-20）：产品库只作目录参考**（非标每台配置不同，选品自动算价难；报价以手工定制为主、可调历史价）

### 【C 订单 / 回款 / 单据】
- **Q7** 库里 283 订单 / 458 回款 / 271 发票，是**真实历史业务数据**吗？还是演示/测试数据？ → ✅ **已决（2026-07-20）：部分真实部分测试**（需清洗：保留真实、清掉测试数据后再作基线；已纳入范围）
- **Q8** 外销 PI / CI / PL 单据，CRM 要不要**内嵌生成**？还是 PI 仍走现有方式、系统只管订单回款？ → ✅ **已决（2026-07-20）：内嵌生成 PI/CI/PL**（CRM 订单模块内嵌单据生成，对齐外销流程；新前端已有打印模板能力）

### 【D 组织与权限】
- **Q9** 实际用系统的角色就哪几个？总经理 + 销售 + 财务？采购 / 仓管 / 生产这些角色**现在有专人吗**（11 人可能一人多岗）？ → ✅ **已决（2026-07-20）：全角色框架保留，权限后续按角色定**（8 类角色体系按文档保留，权限粒度逐角色后定，不阻塞当前）

### 【E 范围校准】

## 五-B、修订后 MVP 范围 v2（2026-07-20 收敛）

> 依据 Q1–Q10 全部已决结论 + 2026-07-20 最终裁定「双系统」。架构 = 统一客户主数据池（一份）+ 内销/外销**双运营系统**（每套含独立线索/商机/跟进/报价/订单/回款/售后）。模块按双系统分建。

### 模块清单（统一客户池 × 双运营系统）
| 模块 | 统一客户池 | 内销运营系统 | 外销运营系统 | 备注 |
|------|------|------|------|------|
| 登录 / 权限 | ✅ | ✅ | ✅ | 共用，RBAC 按角色（Q9：8 类框架保留） |
| 客户主数据 | ✅ 一份（customers/contacts） | 引用 | 引用 | 双系统共享，只录一次（Q1 最终裁定） |
| 线索管理 | ✅ | ✅ | 来源标记（Q2：需要线索阶段） |
| 商机管理 | ✅ 简化阶段 | ✅ 简化阶段 | 单台/单笔意向，4 档（Q3） |
| 跟进记录 / 计划 | ✅ | ✅ | SFA 闭环（Q4） |
| 产品目录 | ✅ | ✅ | 只作目录/历史价参考（Q6） |
| 报价 | ✅ 合同报价 | ✅ 报价 + PI/CI/PL 内嵌 | 系统生成 + Excel 导出（Q5、Q8） |
| 订单 / 回款 | ✅ 人民币 | ✅ 多币种 + PI 关联 | 283 订单/458 回款为基线（Q7 需清洗打标） |
| 审批 | ✅ | ✅ | 已有审批引擎 |
| 看板 | ✅ | ✅ | 分渠道指标 |

### 负责人须提示的风险（Q10=双通道同步首版 的代价）
1. **首版更重、上线更慢**：模块约翻倍，建议**建序仍先外销后内销**（外销是主营收、1000+客户、数据已在库），两里程碑同属"首版程序"，但外销先可跑通验证、降低整体风险。
2. **数据清洗须同时打 channel 标**：现有 394 客户未区分内外销，Q7 清洗时必须补 `channel` 字段，否则双通道建好客户会混。
3. **数据模型需加 `channel` 判别字段**：customers / leads / opportunities / quotes / orders 全加，单号序列内外销分流（外销 PI 编号 / 内销 合同编号）。
4. **原《OA-MVP执行拆解-动作级》需升 v2**：C1（已完）不变，C2–C7 须按本范围重拆（前端 API 层 + 客户/线索/商机/跟进/报价双通道 + 数据清洗打标 + 审批/看板）。
