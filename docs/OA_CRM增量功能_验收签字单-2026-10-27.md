## 二、铁律核验（逐条实证）

### 铁律 1：销售角色判定（禁 `role === 'SALES'`）

**判定：本次 18 个提交范围内 ✅ 无违规；但存量存在 7 处违规，需主线统一安排。**

本次新增/修改的后端文件（`opportunity.service.ts`、`opportunity.repository.ts`、`opportunity.controller.ts`、`payment.controller.ts`、`deal-flow.service.ts`）**均未使用 `role === 'SALES'`**，而是采用正确模式：

- `backend/src/middleware/salesType.ts:37-39`：`resolveRole(req.user.role)` → `deriveSalesType(role)` → 写入 `req.scope`
- `backend/src/services/opportunity.service.ts:46,91,99,124,167,187,198`：一律以 `ctx.scope` 做域判定，非角色字符串比较 ✅
- `backend/src/routes/opportunity.routes.ts:18,25`、`routes/payment.routes.ts:9-12`：均挂载 `enforceSalesTypeScope` ✅

**⚠️ 存量违规（P0，不在本次 18 提交范围，实测 `git log 14ff856~1..HEAD -- <file>` 全部为空，确认非本次引入）：**

| 文件:行 | 内容 | 风险 |
|---|---|---|
| `backend/src/controllers/customer.controller.ts:500` | `req.user?.role === 'SALES' && customer.salesOwnerId !== req.user.id` | 恒 false → 归属过滤失效 → 销售可见全部客户 |
| `backend/src/controllers/customer.controller.ts:606` | 同上（更新路径） | 同上 |
| `backend/src/controllers/customer.controller.ts:941` | `...(req.user?.role === 'SALES' ? { salesOwnerId: req.user.id } : {})` | 恒 false → 未按归属收敛列表 |
| `backend/src/controllers/customer.controller.ts:981` | 同上 | 同上 |
| `backend/src/controllers/report.controller.ts:31` | `req.user?.role === 'SALES'` | 恒 false → 报表数据越权 |
| `backend/src/controllers/followUp.controller.ts:45` | `req.user?.role === 'SALES'` | 恒 false → 跟进记录越权 |
| `backend/src/controllers/target.controller.ts:28` | `req.user?.role === 'SALES'` | 恒 false → 目标数据越权 |

**为何判定为 P0（而非理论风险）：**
`backend/src/constants/roles.ts:96` `resolveRole()` 将历史值 `'SALES'` 归一化为 `'INTERNAL_SALES'`（测试 `backend/src/__tests__/roles.test.ts:23` 已固化该行为）；且 `backend/src/services/rbac-sync.service.ts:131-133` 会对 DB 中的角色做归一化落库。
**一旦角色归一化为 `INTERNAL_SALES` / `EXTERNAL_SALES`，上述 7 处 `=== 'SALES'` 判定永久为 false，过滤分支被静默跳过 → 销售看到全部数据 = 越权。** 与铁律描述完全一致。

相关（非判定，仅口径不一致，P2）：`auth.controller.ts:24`、`auth.service.ts:68`、`wecom-oauth.service.ts:182` 仍以 `'SALES'` 作为默认建号角色值；`constants/enums.ts:70` 保留 `SALES: 'SALES'`。经 `resolveRole` 映射后可正常工作，但与权威角色口径不统一，建议一并收敛。
