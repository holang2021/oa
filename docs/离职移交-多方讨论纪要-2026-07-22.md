# 离职移交机制多方讨论纪要（2026-07-22）

> 议题：离职移交在「客户聚合根 H-4 + Q1 三种方式已确认」下的剩余细节（Q2–Q6）统一
> 机制：治理专家主持，2 轮真讨论（有交叉引用），依 SOP 第三节"已确认问题由团队讨论直到达成统一，不轻易升级"
> 参会：holang-tech-lead（建设） / holang-gas-sales（员工日常） / de-arch-assistant（数字员工）
> 结论：**Q2–Q6 全数收敛一致，无升级项**

---

## 一、第 1 轮分歧点
- Q2 退公海未结业务要不要二级确认：tech-lead 反对(原因必填即可) / gas-sales 要(防错) / de-arch 轻量二级(AI预填+主管点确认)
- Q3 要不要显式交接说明字段：tech-lead 不要(读聚合快照) / gas-sales 强烈要 / de-arch AI摘要替代人工
- Q4/Q5/Q6 三方实质一致

## 二、第 2 轮收敛结论（统一）

### Q2 轻量二级确认（三方接受）
- 主管点「退公海」时，AI 自动弹出**未结业务清单**（在谈商机/在途合同/未回款，预填+大额标红）。
- 主管**看一眼点"确认退公海"即生效**——一次性点选、不阻断流程。
- **原因字段可选备注（非必填）**，卸下填写负担。
- **确认动作留痕**：操作人+时间戳+未结清单快照，作审计证据链（采纳 tech-lead 追溯诉求，放弃原因必填）。
- 守 H-3 红线：AI 只预填/提醒，确认由人点选，不代签。

### Q3 自动摘要 + 可选备注（三方接受）
- **不维护独立"交接包"持久化字段**（唯一真相源=客户聚合快照，避免双份数据源）。
- 系统**自动生成交接摘要卡片**（AI 读聚合快照→NL 总结：进展/卡点/待办/风险），必出。
- **可选自由文本"交接备注"字段**（非必填，挂在事件流水/快照上，不新建实体）：供原负责人手写隐性信息（客户脾气/未说破承诺）；移交触发时主动提醒填写、建议化非强制。
- 既满足 tech-lead 不双份数据源、又满足 gas-sales"5 分钟懂现状"。

### Q4 主管自身离职（一致）
- 数字员工**自动检测**主管状态=离职且无接手触发人 → 告警上级主管/管理员 + 移交任务重路由。
- 上级主管/管理员可**越级代发起**移交（复用 Q1 一键逻辑），不卡流程。

### Q5 历史数据看不可改（一致）
- 历史记录（`created_by`/历史跟进/已归档合同）置只读（前端只读视图 + 服务端写权限拦截）。
- 现 owner 对进行中部分可改；**允许新建跟进/变更记录挂原客户**（写新不改正），兼顾保真与连续性。
- RBAC 自动切只读，免人工逐项配置。

### Q6 署名保留（一致）
- `owner_id` 变更不改 `created_by` 与历史跟进 `author`（不可变字段）。
- UI 区分"当前负责人 / 原创建人"；退公海认领/移交后自动打「原负责人 X（已离职）」标签，默认显示、可追溯、不覆盖。

## 三、行动项（入总纲+流程图+移交工作流）
1. 离职移交 = 独立「移交工作流」：触发(HR标记离职/禁用登录) → 主管裁量三方式 → 退公海走 Q2 轻量二级确认 → 聚合整体移动(H-4) → audit_log 全留痕。
2. 技术实现：未结清单预填(de-arch 数字员工)、确认留痕、只读视图+写权限拦截、署名冻结标签。
3. 进总纲框架「公海设计」补全 + 流程图「公海区」加离职移交/一键移交入口（v1.4）。
