## 0. 结论（一句话）

核心表 `huobanId String? @unique` 已存在于 Prisma schema（Customer / Order / Payment / Lead / Contact / Invoice / Delivery / Quote / Opportunity / ContractEntity），**可直接作为伙伴云 → OA 的迁移映射键**，无需改表；本批次仅立契约，**不跑实际迁移**（留批次1）。

| 项 | 值 | 说明 |
|---|---|---|
| 权威 SoR | **OA** | 伙伴云仅作为历史数据**导入源**，导入后 OA 为唯一可写权威 |

## 4. Upsert 规则（按 huobanId 匹配）

伪代码（批次1 实现参考，本批次不执行）：

```
for each 伙伴云记录 r:
    existing = OA.<Model>.findUnique({ where: { huobanId: r.id } })
    if (!existing):
        OA.<Model>.create({ data: { ...map(r), huobanId: r.id } })   // 插入
    else:
        if (字段冲突 且 OA 值非空/已自定义):
            保留 OA 值（SoR=OA）
            写入 migration_dirty_log { huobanId, field, huobanValue, oaValue }
        else:
            OA.<Model>.update({ where:{huobanId:r.id}, data: mapChanged(r) })  // 仅更新变化字段
```

要点：
1. **匹配键 = `huobanId`**，不依赖 OA 自增 id（避免错配）。
2. **冲突以 OA 为准**（KEEP_OA），不静默覆盖真实业务数据。
3. **仅更新变化字段**，降低写放大与误改风险。
4. 全程在**事务**内执行（Repository 层 `prisma.$transaction`），保证批次原子性。

## 5. 脏数据日志约定

- 无法按 `huobanId` 匹配且无法推断归属、或字段类型/枚举非法、或冲突需留痕时：
  - **不静默丢弃、不抛异常中断整批**；记录到 `migration_dirty_log`（见 `sor.ts.DIRTY_DATA_POLICY.logTable`）。
  - 日志字段建议：`huobanId` / `sourceTable` / `field` / `huobanValue` / `oaValue` / `reason` / `createdAt`。
  - 批次1 提供「脏数据复核台」供人工裁决后再回流。
- 本批次**不建 `migration_dirty_log` 实体**（仅契约预留），避免超出批次0范围。
