# HOLANG OA 增量开发节拍（常备 SOP）

> 定位：把"做一点想一点改一点"变成"固定五步、每轮只动一件、走完才开下一轮"。
> 适用：OA 系统 + 网站建设所有模块。非技术人员照此跑，零代码操作。
> 配套资产：单线推进看板 / OA UI 规范 / 本地预览 SOP / 范围锁纪律。

---

## 一、三条铁律（开工前默念）

1. **单线**：并行项目只留 1 条主线，其余冻结进看板待办池。
2. **原型先确认**：没出可见原型、你没说"像"，绝不开写码。
3. **减法收口**：每周砍一次发散项，多版本原型合并归档。

---

## 二、五步增量循环（每次只跑一轮）

| 步 | 动作 | 你说 / 我做 | 闭环标志 |
|---|---|---|---|
| **1 选增量** | 从看板挑当前唯一 1 个模块，写一行范围锁 | 你说"做 X"，我写范围锁 | 范围锁写死（只做 X，不做 Y/Z） |
| **2 出原型** | 按 OA UI 规范出可见 HTML（含真实 logo） | 我出原型文件 | 原型生成，可预览 |
| **3 你拍板** | 看一眼说"像 / 不像" | 你回"像"或"改哪" | "像"才进下一步 |
| **4 写码验证** | 派 CodeBuddy 写码 + 本地预览跑通真实数据 | 我 + CodeBuddy | 本地 5173 可看真实数据 |
| **5 验收收口** | 你验收 → 写续接文档 → 进下一轮 | 你验，我记 | 续接文档落盘 |

**铁则**：每轮只动 1 个模块、只走 1→5 一遍。不叠加、不回头改上一轮。

---

## 三、非技术视角的"你说我做"对照

| 循环步 | 你只需说（原话照抄） | 我自动做 |
|---|---|---|
| 1 选增量 | "本期做【报价列表】，不做编辑页" | 写范围锁进看板，冻结其余 |
| 2 出原型 | "出报价列表原型" | 按 UI 规范生成 HTML，含 logo |
| 3 拍板 | "像" / "把表头改深蓝" | 确认或改原型 |
| 4 写码 | "转 CodeBuddy 写码" | 派码 + 本地验证 |
| 5 收口 | "验收通过" | 写续接文档，下一轮待你选 |

---

## 四、节拍节奏（建议）

- **每轮增量**：1 个模块，从看板"①原型待确认"列从左到右推。
- **每周一 09:00**：自动化提醒你做两件事——① 选下一增量写范围锁 ② 减法收口（合并多版本原型 / 砍发散项）。
- **大模块拆分**：一个模块超过 3 天还走不完 → 拆成子增量，不要硬撑一整轮。

---

## 五、复用资产索引（不重造）

- 单线推进看板：`docs/OA与网站_单线推进看板.html`（backlog + 状态）
- UI 规范：`docs/OA_UI_Foundation_V0.1.md` + `oa-design-tokens.css/json`（"像"的标准）
- 本地预览 SOP：`docs/OA本地预览启动指南.md`（第 4 步验证手段）
- 范围锁 / 减法收口：已锁定的建设纪律（总纲 + 防发散四条闸门）

---

## 六、禁止事项（防发散）

- ❌ 原型没确认就开写码。
- ❌ 一轮同时动 2 个以上模块。
- ❌ 顺手加客户没要的功能（指不到来源就删或单列待确认）。
- ❌ 同一模块堆 3+ 版原型不收敛。
- ❌ 跳过第 5 步收口（不写续接 = 下次重新想）。

---

## 七、卡住时怎么办

- **本地能跑但没服务器**：按本地预览 SOP 本机验，不阻塞（详见该 SOP）。
- **"越做越不像"**：回第 3 步重看 UI 规范，不擅自全局重构，走三页验证法再 Freeze。
- **不知道做哪个**：等每周一自动化提醒，或随时说"帮我选下一增量"。
