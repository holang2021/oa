## 5. 不明确的事项

### 5.1 WhatsApp Business API接入方式

**问题**：WhatsApp Business API有两种接入方式：
1. **官方API**（直接向Meta申请，需要审核，周期长）
2. **第三方提供商**（如360dialog、Twilio，快速接入，但按消息收费）

**当前方案**：使用 **360dialog**（快速接入，无需Meta审核）

**需要确认**：
- 刘总是否接受第三方提供商？（按消息收费，约¥0.05/条）
- 或者愿意等待Meta审核？（审核周期1-2周）

### 5.2 邮件同步方案

**问题**：邮件同步需要读取用户的邮件（IMAP协议），需要用户的邮件账号和密码

**方案**：
1. **用户手动配置**（在每个用户的设置页面填写邮件账号和密码）
2. **使用企业邮箱API**（如腾讯企业邮箱API）

**当前方案**：使用 **IMAP协议**（用户手动配置）

**需要确认**：
- 刘总希望使用哪种方案？
- 是否使用企业邮箱？

### 5.3 低代码配置引擎的复杂度

**问题**：低代码配置引擎可以实现很复杂（拖拉拽、条件分支），也可以很简单（表单配置）

**当前方案**：**表单配置**（简单直观，不需要拖拉拽）

**需要确认**：
- 刘总对低代码配置的预期是什么？
- 是否需要拖拉拽？（建议Phase 2再做）

### 5.4 统一沟通视图的消息实时性

**问题**：沟通记录需要实时同步，还是可以延迟几分钟？

**当前方案**：**Webhook实时推送**（WhatsApp、企微） + **定时同步**（邮件，每10分钟）

**需要确认**：
- 刘总对实时性的要求？

### 5.5 审批流通知财务的具体方式

**问题**：审批通过后通知财务（系统内抄送 + 企微消息），但财务可能不是CRM系统的用户

**当前方案**：**财务是CRM用户**（创建财务账号，分配finance角色）

**需要确认**：
- 财务是否需要登录CRM系统查看变更记录？
- 或者只需要在企微收到通知即可？

## 8. 共享知识

```
# API响应格式
{
    "code": 0,
    "data": {...},
    "message": "success"
}

# 错误码定义
- 400: 请求参数错误
- 401: 未认证
- 403: 无权限
- 404: 资源不存在
- 500: 服务器内部错误

# 认证方式
- Header: Authorization: Bearer {JWT_TOKEN}
- Token过期时间：24小时
- 企微免登录：使用企微UserID

# 日期时间格式
- API请求/响应：ISO 8601（YYYY-MM-DDTHH:mm:ss）
- 数据库存储：UTC时间
- 前端显示：转换为用户时区（默认Asia/Shanghai）

# 文件上传
- 格式：multipart/form-data
- 大小限制：10MB
- 允许类型：.pdf, .jpg, .png, .doc, .docx

# 分页参数
- page: 页码（从1开始）
- page_size: 每页数量（默认20，最大100）

# 权限控制
- 销售：只能查看自己的数据
- 主管：可以查看团队的数据
- Admin：可以查看所有数据
- Finance：可以查看客户变更记录

# 企微通知场景
- 公海池回流：通知当事人
- 周报提交：通知主管
- 周报审批：通知销售
- 客户变更审批通过：通知财务

# 沟通记录同步（v2.0 新增）
- WhatsApp：通过Webhook实时同步
- 邮件：通过IMAP定时同步（每10分钟）
- 企微：通过API定时同步（每10分钟）

# 工作流引擎（v2.0 新增）
- 工作流配置在 workflows 表
- 管理员可在操作后台配置

# WhatsApp集成（v2.0 新增）
- 使用360dialog作为提供商
- 用户在CRM系统中绑定WhatsApp账号

# 内外销区分（v2.0 新增）
- users表和customers表增加sales_type字段
- 前端根据sales_type显示不同菜单
```

## 11. 风险评估（v2.0）

### 11.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| WhatsApp API接入失败 | 高 | 中 | 使用360dialog作为备用 |
| 邮件同步失败 | 中 | 低 | 使用企业邮箱API |
| 工作流引擎复杂度超预期 | 中 | 中 | 先实现表单配置 |
| DeepSeek API调用失败 | 低 | 低 | 增加缓存和重试 |

### 11.2 进度风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 需求变更频繁 | 高 | 中 | 每周与刘总确认需求 |
| 开发工时超预期 | 中 | 中 | 按优先级开发 |
| 测试发现问题多 | 中 | 低 | 边开发边测试 |

### 11.3 成本风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| DeepSeek API费用超预期 | 低 | 低 | 增加缓存机制 |
| WhatsApp费用超预期 | 低 | 低 | 限制同步消息数量 |
| 服务器资源不足 | 中 | 低 | 配置资源监控 |
