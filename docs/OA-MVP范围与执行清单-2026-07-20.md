## 二、MVP 范围（冻结）

**IN（当前必须有的，11 人销售驱动公司）：**
- 企微 OAuth 登录 + 基础角色权限
- 客户管理（CRUD / 列表 / 检索）
- 产品管理（CRUD / 分类）
- 报价管理（选品 / 算价 / 生成 PDF）—— *新前端已建，需接生产数据*

- 审批引擎（报价/订单提交 → 审批流）—— *新前端已建*
- 首页看板（核心指标卡）

**OUT（后移，不在 MVP，列名即可不展开）：**
- 线索/商机公海池、代理商报备深化、伙伴云 API 对接
- SRM / 供应商 / 采购 / 仓储
- 生产 / BOM / 工单
- 财务模块（应收应付 / 发票 / 报销）
- AI 报表 / RAG 知识库
- 表单打印设计器（建设草案内容，先冻结）

## 四、上线切换四步（冻结旧 → 接数据 → 部署新 → 退场旧）

2. **接数据**：新前端指向现有 Express + SQLite（复用 holang-oa 后端），本地 JSON 仅留开发期 mock。
3. **部署新**：按现有上线通道部署 `holang-oa-frontend`，域名 `oa.holangchina.com` 切到新前端。
4. **退场旧**：验证无误后，旧前端停止访问；`holang-oa` 后端保留为数据底座。

## 附：《业务目标拆解》（简版）

- **原始需求**：OA 一步做一步改太慢，梳理进度、定下一步
- **真实目标**：提升建设效率 + 让系统被日常用起来（效率 + 体验）
- **成功指标**：单一可部署 OA；员工日活；功能上线周期从「月」降到「周」
- **根因**：决策/流程问题（架构反复 3 次、范围未冻结、双系统并存），非系统能力不足
- **判断**：B 优先治理（冻结范围 + 切换决策），A 中 MVP 收尾

## 附：《流程治理分析》（简版）

- **当前流程**：OA 建设自身（需求→架构→开发→上线）无冻结点，每会话重开范围
- **问题**：无限规划、双系统并行、无 Done 定义
- **根因**：E 综合（决策 + 系统并存）
- **优化**：冻结范围 → 单系统 → 定义 Done → 短周期；系统已够，问题在治理
