# HOLANG CRM 客户关系管理系统 — 分阶段建设方案

> 版本：V1.0 | 日期：2026-06-26 | 状态：DRAFT

---

## 一、系统总览

基于 CRM 设计方案 Excel（8 大模块 / 79 行功能清单）及现有报价单模板，将 HOLANG CRM 系统拆分为 **7 个阶段**逐步交付，每个阶段产出可独立运行的功能模块。

### 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    HOLANG CRM 系统                         │
├──────────┬──────────┬──────────┬──────────┬─────────────┤
│ P1 基础   │ P2 销售   │ P3 市场   │ P4 财务   │ P5 数据      │
│ 框架     │ 管理     │ 营销     │ 售后     │ 分析        │
├──────────┼──────────┼──────────┼──────────┼─────────────┤
│ P6 集成与 AI           │ P7 供应链与生产                    │
└─────────────────────────────────────────────────────────┘
```

---

## 二、分阶段方案

### Phase 1 — 基础框架 + 产品与客户管理 🔵 [当前阶段]

**目标**：搭建可运行的后台管理系统骨架，完成最核心的两大基础数据模块。

| 编号 | 模块 | 功能点 | 来源 |
|------|------|--------|------|
| 1.1 | 登录页 | 账号密码登录、记住密码、登录态保持 | 新增 |
| 1.2 | 首页看板 | 线索数/商机数/成交金额/回款金额卡片、销售漏斗图、业绩趋势 | 设计稿 §1.1 |
| 1.3 | 产品管理 | 产品CRUD、分类筛选（氮气/氧气/氢气）、规格型号、成本/售价、图片上传 | 设计稿 §2.1 |
| 1.4 | 客户管理 | 客户CRUD、行业/等级/区域筛选、联系人子表、开票信息 | 设计稿 §4.1 |
| 1.5 | 框架层 | 侧边导航、顶部搜索、用户信息、响应式布局（PC/平板/手机） | 新增 |

**技术栈**：React 18 + TypeScript + Vite + Tailwind CSS + Recharts + React Router

**交付物**：
- 可本地运行的前端应用
- 产品管理列表 + 表单编辑
- 客户管理列表 + 表单编辑
- 数据看板（模拟数据）
- 响应式适配

---

### Phase 2 — 销售管理（商机 / 报价 / 合同）

**目标**：打通「线索→商机→报价→合同」核心销售管道。

| 编号 | 模块 | 功能点 | 来源 |
|------|------|--------|------|
| 2.1 | 商机管理 | 商机CRUD、阶段流转（目标客户→拜访→需求确认→技术交流→立项→谈判→签单）、跟进计划/记录、公海回流 | 设计稿 §5.1 |
| 2.2 | 报价管理 | 报价单CRUD、基于产品库选品、自动计算含税/不含税/毛利/折扣、一键生成PDF报价单（对齐现有报价单模板）、版本管理 | 设计稿 §5.2 + 报价单Excel |
| 2.3 | 合同管理 | 合同CRUD、关联报价单自动带入、交付状态跟踪、财务条款 | 设计稿 §5.4 |
| 2.4 | 发货通知 | 发货申请、审批流、出库执行 | 设计稿 §5.5 |

**重点**：报价单模块 — 对齐现有 Excel 报价模板（客户信息+产品明细+价格计算+备注条款），编号自动生成。

---

### Phase 3 — 市场营销 + 渠道对接

**目标**：构建获客体系，接入外部渠道。

| 编号 | 模块 | 功能点 | 来源 |
|------|------|--------|------|
| 3.1 | 市场活动 | 活动CRUD、渠道类型（展会/伙伴/品牌/广告/直播/其他）、投入产出跟踪 | 设计稿 §3.1 |
| 3.2 | 销售线索 | 线索CRUD、来源跟踪（活动/社媒/电话/官网/公众号/抖音）、分配/认领/回流、转化状态 | 设计稿 §3.2 |
| 3.3 | 代理商报备 | 官网预留报备入口、代理商信息登记、报备审核流程 | 用户需求 |
| 3.4 | 公众号对接 | 在线客服入口、公众号粉丝→线索转化 | 用户需求 |
| 3.5 | 伙伴云API | 对接伙伴云（Huobanyun）开放API，实现数据互通 | 用户需求 |
| 3.6 | 日报/周报/月报 | 销售日报CRUD、周报/月报AI自动生成（预留）、按人员/部门汇总 | 设计稿 §1.5~1.7 |

**说明**：日报/周报/月报为**预留框架**，后续由 AI 模块驱动自动生成。

## 三、技术决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 前端框架 | React 18 + TypeScript | 生态成熟、组件丰富 |
| 构建工具 | Vite | 开发体验优于 Webpack |
| UI 方案 | Tailwind CSS | 响应式友好、开发效率高 |
| 图表库 | Recharts | React 原生、轻量 |
| 部署方式 | CloudStudio / 静态托管 | 全部云端化 |
| 后端（后续） | 待定（建议 Node.js / Python + PostgreSQL） | 当前 Phase 1 纯前端 |

---

## 四、风险与边界

1. **Phase 1 为纯前端**：使用 Mock 数据，后续 Phase 需要对接后端 API
2. **报价单编号规则**：格式 `HQ + 日期 + 流水号`（如 HQ26041006），可实现自动生成
3. **审批流**：Phase 1 暂不实现，Phase 2~4 逐步引入
4. **实时通知**：依赖 Phase 6 企微集成
5. **数据安全**：后续需实现角色权限（管理员/销售总监/销售员/财务）
