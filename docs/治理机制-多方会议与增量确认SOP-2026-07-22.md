# HOLANG 治理机制：多方会议与增量确认 SOP（v1.0）

> 生效：2026-07-22 刘总两次纠偏后固化。治理专家必须执行，定期审计。

## 一、背景（刘总纠偏点）
1. **确认事项被攒批**：一次性甩一大批文件+确认项，未在中途随问随讨论 → "决而不议"。
2. **会议无讨论**：用并行独立 agent 各自产出，无交叉引用、无来回 → "会而不议"。
本 SOP 固化正确机制，杜绝上述两种失败。

## 二、增量确认机制（针对"确认事项"）
1. 任何确认项，由**提出方**（业务专家或治理）在**产生时即时**向刘总提出，**不攒批**。
2. 每次只问**一个聚焦问题**（或一组强相关小问题），附极简上下文，**不一次性附大批文件**。
3. 中途随时问、随时讨论；讨论达成即形成共识，记入纪要，继续下一项。
4. 治理专家**不代替**业务专家攒批确认——"谁的方案谁去确认"。

## 三、多方会议机制（针对"具体事情"）
原则：**会必议，议必决，决必行**。
1. 会议围绕**一个具体议题**（不泛泛而谈、不一次塞多主题）。
2. **2–3 轮多轮发表（必须有交叉引用）**：
   - 第 1 轮：各方基于共享上下文独立发表初见。
   - 第 2 轮：各方**读取彼此第 1 轮观点**，引用/赞同/反驳/补充（禁止自说自话）。
   - 第 3 轮（如需）：仅针对第 2 轮仍存在的分歧，各方给最终立场。
3. **收敛**：治理专家汇总为 共识 / 分歧 / 行动项。
4. **升级拍板**：2–3 轮后仍有争议的项 → 整理成**待刘总拍板清单**（每项附各方立场+建议），交刘总决。
5. **已确认问题不下沉争议（刘总 14:55 补充）**：凡**刘总已确认/拍板**的方向性问题，允许各方针对该问题继续发表意见、**讨论直到达成统一**，不轻易升级回刘总；只有"新出现的、刘总从未表态过"的争议才走升级拍板。即：已决事项由团队自行收敛统一，刘总不被反复打扰。
5. **决必行**：刘总拍板后，决议写入纪要+资产，路由执行方落地。

## 四、与现有治理流程衔接
- 复用闸门 A/B/C、总纲对照表、数字负责人行动卡 等机制不变。
- 会议产出 = 数字负责人行动卡 + 会议纪要，回传中枢(holang-digital-product-owner)路由执行方。
- 本 SOP 纳入治理运行资产，季度审计。

## 五、红线（违反即纠正）
- ❌ 用并行独立 agent 当"会议"（那是无讨论的各自产出）。
- ❌ 把确认项攒成一批大文件甩出。
- ❌ 争议无限讨论——2–3 轮即升级刘总拍板。
