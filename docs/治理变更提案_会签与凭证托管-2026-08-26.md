# 治理变更提案：会签机制 + 基础设施凭证托管（2026-08-26）

> Status: 已批准（2026-08-26 刘总拍板）· 中枢（holang-digital-product-owner）端到端负责执行
> 背景：系统建设反复卡在"待刘总会签/待立项/待提供服务器凭证/域名未解析"，07-28~08-08 未闭环清单持续出现。根因是**决策权与基础设施凭证单点压在 L0**，全链路串行阻塞。本提案把 L0 从"操作工"还原为"决策者"。

---

## 一、问题（现状）

| 环节 | 现状痛点 | 证据 |
|------|----------|------|
| 会签 | 每个功能逐一等刘总看实物+签字，时间稀缺 → 功能排队 | 未闭环清单 "待刘总会签/待确认范围" |
| 基础设施 | 服务器登录、域名 DNS、企微 secret 都在刘总手上，tech-lead 无法独立完成部署 | "无有效生产服务器登录凭证+域名未解析" 阻塞上线 |
| 部署 | 手搓脚本高风险，需刘总亲审 → 反过来加重串行阻塞 | 部署文档含 rm-rf backend 删库风险 |

## 二、变更 1：会签改为"里程碑批量"

- **保留**刘总的最终确认权（不削弱治理）。
- **改方式**：从"逐功能签字"改为"原型/里程碑批量会签"——每个里程碑（如一批功能）只看一次实物、签一次，范围内 tech-lead 自主部署，不再反复打扰。
- **授权**：已确认范围内，tech-lead 拥有自主部署与回滚权（回滚预案已存在）。
- **仍触发刘总会签的情形**：新增业务域、数据安全策略变更、对外暴露接口、角色/权限模型调整。

## 三、变更 2：基础设施凭证一次性安全托管

- 服务器登录、域名 DNS 管理、企微应用 secret 做一次性的安全托管：
  - 凭据存入密钥管理（如凭据托管服务 / 加密仓库），不每次堵在刘总手上；
  - tech-lead 在受控流程（审计留痕）中取用，刘总不再当"操作工"。
- 域名 DNS 改为一次性授权 tech-lead 在控制台操作（或委托托管账号）。

## 四、预期效果

- 刘总从"每个环节操作工"→"只拍板里程碑范围的决策者"，时间占用降一个数量级。
- 部署从"手搓高风险脚本"→"Runner 自动执行"（见 `.github/workflows/deploy.yml`），tech-lead 可独立闭环。
- 全链路从串行阻塞变为：开发自测 → 里程碑会签 → 自动部署。

- [x] 同意基础设施凭证一次性安全托管：服务器登录 / 域名 DNS / 企微 secret 托管后，tech-lead 受控取用（审计留痕），刘总不再当操作工。
- [x] 授权范围清单认可：新增业务域、数据安全策略变更、对外暴露接口、角色/权限模型调整 仍须刘总会签。

> 自此 L0 从"每个环节操作工"还原为"只拍板里程碑范围的决策者"。

## 六、执行 SOP（中枢端到端负责）

1. **里程碑批量会签**：每批功能（如 GOV-2026-026 快赢）本地 fork 跑通后，刘总只看一次实物、签一次；范围内 tech-lead 自主部署。
2. **凭证一次性托管**：新服务器到位后，刘总在控制台将服务器登录 / DNS / 企微 secret 一次性托管（加密凭据库，不进脚本不进仓库）；tech-lead 受控取用并审计留痕。
3. **自主部署闭环**：tech-lead 按 `holang-oa/deploy/harden-tat-cos.md` 硬化方案执行（TAT+COS / WAL / migrate deploy / 每日备份），部署结果与回滚预案留痕。
4. **仍触发刘总会签**：新增业务域 / 数据安全策略变更 / 对外暴露接口 / 角色权限模型调整 —— 中枢不得自行拍板，统一走会签。

> 中枢对事项端到端执行与闭环负全责；内部分工由中枢拆解，不把问题抛回刘总。
