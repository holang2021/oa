PI「人民币参考 / 汇率」改动对照

2026-11-08 · 依据刘总意见：人民币参考是否不显示在 PI；汇率没有写入；系统已设计过汇率计算方式
结论：客户能看到的 PI 单据上，不显示人民币金额、也不显示汇率——真实 Allum 形式发票只有外币金额 US$14,328.00 和英文大写，没有人民币列。
内部仍可看折算做参考，但汇率统一取系统设置里那张汇率表，不再由 PI 页面自己写死数字。

代码里写的是 USD × 7.27 / EUR × 7.85 / 其他 × 1；系统设置里的汇率表完全没被调用。
  • 汇率写死在页面里，系统设置改了汇率也没用。
  • 「人民币金额（参考）」不落库、不参与保存，却占着一个显眼输入框，容易被误认为会打给客户。
  • 币种下拉与系统币种表是两套，新增币种这边看不到。
  • 打印模板把币种写死成 US Dollar，选 EUR 也会印错。

内部参考（不输出到给客户的 PI / PDF）：按系统汇率约折合 ¥103,878.00；采用 1 USD = 7.25 CNY，可在「系统设置 → 币种与汇率」维护。
  • 删除写死的 7.27 / 7.85；改用系统 convertToCNY()。
  • 「人民币金额（参考）」输入框撤掉，只留一行小字，且明确标注不进客户单据。
  • 币种下拉直接取系统币种表（含新增币种）。
  • PI / CI 打印的币种名称按单据实际币种输出，不再写死 US Dollar。

汇率真源链路（这次真正接通的部分）

系统设置 → 币种与汇率后端 currencies 表，6 个币种；增删改仍只有管理员能做
→
initCurrencies()打开 PI 表单 / 列表时从后端预热汇率
→
convertToCNY()系统已设计好的换算函数：金额 × 汇率
→
内部参考表单一行小字 + 列表「人民币金额（内部参考）」
  • 补了根因 1：汇率表的「读取」原来只有管理员能调，销售开 PI 会被挡住并静默退回默认汇率。现改为所有登录用户可读（只读），写操作仍锁管理员。
  • 补了根因 2：建表 SQL 只建表、不落初始汇率，表是空的；本地预览库甚至没建这张表。现加了幂等初始汇率，并在本地预览库执行，链路实测跑通。
