CI（商业发票）/ PL（装箱单）：从「只有打印模板」到「系统里能开单」

刘总：「PI 先这么的呗，继续做 CI 和 PL」。本轮把两张出货单据接进系统，并落实最早定的原则——同一个客户的 PI / CI / PL 数据互通。

先说清现状：之前系统里 CI / PL 只有打印模板和示例数据，没有录入页面、没有菜单、没有保存通道。销售想开一张 CI 或 PL，只能回到 Word / Excel 手工做——这正是本轮要补的洞。

改前 / 改后

BEFORE

系统里开不了单

  • 外销菜单只有「形式发票 PI」一个入口
  • CI / PL 只存在于「打印模板库」的样张里
  • 客户、产品、数量要重新手打，PI 的数据带不过来
  • 没有保存，做完就没了
  • CI 模板还写死一行 US Dollar
AFTER

系统里能完整开单

  • 外销菜单新增「商业发票 / 装箱单 (CI/PL)」
  • CI / PL 共用一个列表页，Tab 切换（出货时两张一起开）
  • 编辑页可录买方抬头、明细、条款 / 装箱信息
  • 从 PI 一键带出，带出后可改、不回写 PI
  • 能保存草稿、能预览、能导出 PDF

数据怎么「互通」：PI 只是起点，不是枷锁

PI 形式发票
销售已录好的客户抬头、单据头、商品名称 / HS Code / 数量 / 单价、付款条款、交货期
→
CI 商业发票
带出抬头 + 明细 + 条款；补金额大写、EIN 税号、银行信息（按币种自动带账户）
PL 装箱单
带出抬头 + 品名 / HS Code / 数量；补 PACKAGE、毛净重、体积、箱尺寸（PI 没有，不编造）
关键口径：带出只是「一次性拷贝当下事实」。之后三张单据各自独立保存，改 CI 不会动 PI，PI 以后改了也不会覆盖 CI / PL； 来源 PI 只留个编号便于追溯，不是绑定关系。这对应既定总纲「后续单据须能表达自身最终事实」。
